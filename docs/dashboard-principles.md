# A. 확정된 원칙

## A1. 대시보드는 알림센터다

> 「대시보드는 미확인 요청이 모두 보여야돼. 일종의 알림센터 기능을 포함해
> 화면 효율적으로」 (2026-08-07)

**근거** — 대시보드는 가장 자주 여는 화면인데 검사 사각지대였다. 기존 시뮬
4종은 오늘 수업·수강료·경고를 검사했지만, **하루를 시작하는 화면이 그날
알아야 할 일을 다 보여주는지**는 아무도 검사하지 않았다.
2026-07-30 시뮬 결과: **그날 알아야 하는 22건 중 16건(9종)이 안 떴다.**

## A2. 로그인하면 원장은 대시보드로 고정

> 「로그인시 원장 첫화면은 대시보드로 고정하고, 대시보드 메뉴가 두개인것도
> 하나만 살리고」 (2026-08-07)

**근거** — 예전에는 누구든 `/me` 였다. 원장님은 「학생이 없습니다」 를 보시고
다시 대시보드로 옮겨 가셔야 했다. 「원장 로그인하면 학생 화면이 나와」 의
진짜 원인은 계정 역할이 아니라 **로그인이 자리를 하나로 박아둔 것**이었다.
검사: `check-home.mjs` — 원장 `/` · 학부모 `/parent` · 학생 `/me`,
역할을 못 읽으면 `/me` (막다른 곳으로 보내지 않는다).

## A3. 대시보드에서 **바로 처리**까지 된다

> 「대시보드에서 액션으로 이어지는 것도 고려해야해. 읽고 다른 화면 가면
> 내용을 잊어버려. 보강추가, 할일추가 그런거 있어야해」 (2026-08-07)

**근거** — 읽던 자리에서 끝내야 방금 읽은 것이 안 흐려진다.
구현: `app/QuickBar.jsx` (보강 잡기 · 할일 넣기).
- **저장했다고 다른 화면으로 보내지 않는다** (`router.push` 금지,
  `router.refresh` 만)
- **접혀 있다가 누르면 펴진다** — 늘 펴져 있으면 매일 여는 화면 맨 위를
  입력칸이 차지한다

## A4. 뜬 것은 **눌러서 처리하러 갈 수 있어야** 한다 — 막다른 태그 = 실패

**근거** — 2026-07-30 점검의 최우선 기준 두 가지 중 하나.
당시 실측: 배지 모양인데 못 누르는 `<span className="btn">` 2개
(학부모 알림 · 보강 잡을 것), 특이사항 카드 태그도 전부 링크 없음.
→ 지금은 `<span className="btn">` **0개**, 특이사항의 모든 태그가 `<Link>`.

## A5. 배지 숫자는 **무엇인지 알 수 있어야** 한다

> 「지금 알림이 발송과 학생에 있는데 왜 뜬 건지 모르겠어」 (2026-08-08)

**근거** — 숫자만 뜨면 왜 떴는지 모른다.
→ 배지 줄 아래 「남은 일」(`TodoBar`)이 **무엇인지 적는다.**

> 「알림 있는 거 성적 어디서 입력해야 하는지」 (2026-08-08)

**근거** — 배지가 「3명」 이라고만 하면 화면에 들어가서 아이를 하나씩 눌러
찾아야 한다. **그건 배지가 일을 늘린 것이다.**
→ 같은 함수가 **목록도 내주고**, 그 화면이 그대로 펴 놓는다.

## A6. 배지 제목은 **명사로 끊는다**

> 「제목은 명사화해줘. 성적미입력」 (2026-08-08)

**근거** — 「시험은 끝났는데 성적이 아직 안 들어온 학생 3명」 은 맞는 말이지만
한 줄이 길어서 눈이 멈춘다. 대시보드에 열 줄이 나란히 서면 더 그렇다.
명사로 끊으면 훑어진다 — 「성적 미입력 3명」.

## A7. 메뉴마다 남은 일 숫자

> 「해야 할 일이 남은 경우 메뉴마다 알림 배지를 다 추가해줘」 (2026-08-08)
> 「확인 안 한 알람이 있으면 카톡처럼 대시보드 메뉴에 배지로 확인 안 한
> 갯수를 표시해줘」 (2026-08-07)

**근거** — 어디에 일이 남았는지 메뉴에서 바로 보여야 한다.

## A8. **배지는 틀리면 안 뜨느니만 못하다**

**근거** — 「3」 이라고 떠 있는데 들어가서 아무것도 없으면 그다음부터
안 믿게 되고, 그러면 **진짜 3건이 왔을 때도 안 들어가신다.**

파생 규칙 (`check-inbox.mjs`):
- 0 이거나 없으면 **안 그린다**
- 100 이상은 `99+` (세 자리가 되면 메뉴가 밀린다)
- **못 세면 0 으로 본다** — SQL 을 아직 안 돌리셨거나 읽기가 막히면 조용히 0.
  **안 뜨는 것이 잘못된 숫자가 뜨는 것보다 낫다**

## A9. 끌 수 없는 숫자를 만들지 않는다

> 「안 보낸 게 없는데 발송에 알림 밀렸어」 (2026-08-08)

**근거** — 결석해서 보낼 것이 없는 날을 「안 보냄」 으로 치워두시는데, 그것까지
세면 **화면 목록은 비어 있는데 배지만 남는다** — 끌 방법이 없는 숫자가 된다.
→ 「안 보내기」 로 정리한 것은 뺀다. 발송 화면(`notSkipped`)과 같은 기준.

## A10. 같은 정보가 한 화면에 두 번 뜨지 않는다

**근거** — 2026-07-30 점검의 최우선 기준 두 가지 중 나머지 하나.
당시 실측: 보강 잡을 것 · 학부모 알림 · 스케줄 특이사항이 **같은 화면에
배지와 카드로 두 번**.

**해법은 「지우기」 가 아니라 「역할 가르기」**:
> 위는 요약, 아래는 처리 — 배지를 누르면 같은 화면 아래 카드로 앵커
> (`#requests` `#makeup`)로 내려간다.

2026-08-08 에 한 번 더 정리: 배지 줄에서 **미발송 · 보강 잡을 것 ·
월간리포트 · 시험범위 · 진행중 상담 · 지난 할일**을 뺐다.
같은 것을 두 벌로 세고 있었고 **두 벌은 언젠가 서로 다른 말을 한다.**
위에 남은 것은 아래에서 안 세는 것들뿐이다 — 반성문 · 단원평가 막힘 ·
발송 실패 · 학부모 알림 · 보강 필요 회차 · 스케줄 특이사항.

## A11. **없는 것은 안 그린다**

**근거** — 「없습니다」 한 줄도 제목·테두리까지 하면 카드 하나다. 대여섯이면
정작 온 것 하나를 보려고 화면을 한참 내려야 한다.
적용: `RequestInbox` · `InquiryInbox` · `UnsentBox` · `WarningInbox`
전부 비면 `return null`.

## A12. 처리한 것도 남는다 (사라지지 않는다)

> 「제출 후에 나한테는 다 보이게 해줘」 (2026-08-07)

**근거** — 예전에는 `status='new'` 만 받아서 「확인」 을 누르는 순간 사라졌다.
무슨 말을 주고받았는지 다시 볼 수 없었고, 답장을 한 번 더 드리려면 갈 데가
없었다. → 최근 것을 통째로 받아 **화면에서 가른다** (안 본 것 위, 처리한 것
아래 접어둠).

## A13. 어디서 온 것인지 같이 보여준다

> 「아직 결석 안 했고 사전연락 없는데 뭐지」 (2026-08-06)

**근거** — 결석 예정은 세 갈래로 들어온다 (시험 기간 반 단위 · 학부모 요청
수락 · 노션 이관). 출처를 안 보여주면 **「이게 왜 여기 있지」 로 끝나고,
치울 수도 없어서 목록이 점점 무거워진다.**

## A14. 재촉은 **필요한 것만** — 늘 켜져 있으면 안 보이는 것과 같다

> 「대비하는 시험이 아니라서 일정만 확인하면 되고 시험범위자료는 필요없어」
> (2026-08-06, 전국연합학력평가)

**근거** — 모의고사는 그동안 배운 전부가 범위다. **재촉이 늘 켜져 있으면
그 재촉은 안 보이는 것과 같아진다.**

> 「모의고사는 전날 등원 안 해 학교 시험만 그래」 (2026-08-08)

**근거** — 같은 이유. 모의고사는 전국이 같은 날 보고 범위도 전부라 전날 따로
부르지 않는다.

## A15. 알릴 시점을 늦춘다 — 흔해지면 안 들린다

**근거** (단원평가 막힘) — 두 번은 흔하다 (한 번 미끄러지고 다음에 통과).
**세 번째부터** 알린다. **두 번에 알리면 흔해져서 정작 세 번째에 안 들린다.**

## A16. 대시보드 데이터 읽기는 화면에서 빼낸다 (`lib/dashboard.js`)

**근거** — 세 가지가 한 번에 해결된다:
1. 성능 — `await supabase` **25회 전부 직렬** → `Promise.all` 왕복 2번.
   첫 화면 약 1초 → 약 0.1초
2. 시뮬 하드코딩 제거 — 전에는 `page.jsx` 의 판단 규칙을 시뮬에 **옮겨
   적어 뒀는데 그것 자체가 두 번 적는 일**이었다. 이제 시뮬이 `page.jsx` 를
   직접 읽는다 (원칙 1)
3. 배지와 카드가 **같은 데이터 배열 하나**에서 렌더된다

## A17. 학원 상태를 숫자 한 줄로

**근거** — 2026-07-30 점검 기준: 「학원이 지금 어떤 상태인지 숫자 한 줄로
보이는가」. 당시 대시보드에 숫자 지표가 **0개**였다.
→ 제목 아래 한 줄: 재원 N · 이달 출석률 · 오늘 리포트.

## A18. 답할 것만 대시보드에

**근거** — 보강을 잡고 무르는 일은 출결 화면으로 옮겼다. 그런데 어머니가
「그날 시험이라 안 돼요」 하고 누르신 것은 **답할 일**이라, 대시보드에 없으면
그 보강은 잡힌 채로 지나간다.
→ 대시보드에는 `only="changed"` (답할 것만). **확정된 것까지 늘어놓으면
묻힌다.** 전부 보는 자리는 출결 화면.

## A19. 새 페이지를 만들지 않는다

**근거** (수납을 붙일 때) — 셋 다 있던 화면에 붙였다:
올리기 → `/import` 탭 / 보기·고치기 → `/tuition` 버튼 /
알림 → 대시보드 배지.

## A20. 같은 테이블을 두 화면이 나눠 보여주지 않는다

**근거** — `/todo` 와 `/tasks` 는 **같은 테이블(`tasks`)** 을 `kind` 로만
갈라 읽고 있었다. `/report` 와 `/resend` 도 **같은 데이터**(`loadReportRows`)를
읽는데 재발송만 설정 메뉴에 따로 있었다.
→ 화면을 합치고 위에 [통합][일정만][할일만] 탭.
**메뉴 아홉 개 → 여덟 개, 설정 다섯 개 → 네 개.**
옛 주소는 넘긴다 (`/todo` → `/tasks?view=todo`) — 즐겨찾기·홈 화면
바로가기가 안 깨지게.

# B. 폐기 / 거부한 안

## B1. 미납을 대시보드에 알리는 것 — **폐기**

> 「이 앱이 챙기는 것은 수업이다. 수강료는 결제선생에서 따로 보시고,
> 여기서는 수강료 화면에 들어가셨을 때만 보이게」 (2026-08-05)

**버린 이유** — 원장님이 앱의 범위를 그렇게 그으셨다.
계산은 그대로 둔다 (수강료 화면이 쓴다). 되살리려면 `lib/dashboard.js` 의
`const unpaid = []` 한 줄만 바꾸면 된다.
**메뉴 배지에도 안 띄운다** — 띄우면 그 결정을 뒤집는 일이다.

> 이것은 A1(「미확인 요청이 모두 보여야 한다」)의 **명시적 예외**다.

## B2. 출결선생 · 결제선생 API 연동 (50만원) — **권하지 않음, 미실행**

**버린 이유** (2026-07-30 문의 결과):
1. 연 사용액보다 연결 비용이 크다. 학생 수가 적으면 API 가 덜어주는 손도 적다
2. 출결은 앱에 이미 있다 → 연결하면 **출결 기록이 두 군데 살아 있게 된다**
   (중복 금지 원칙 위반)
3. 수납은 **엑셀 내보내기가 된다** (원장님 확인) → `/import` 탭 하나면 0원

## B3. 메뉴를 한 줄로 흘리기 — **폐기 (첫 번째 시도)**

**버린 이유** — 화면 너비에 따라 **묶음이 줄 중간에서 갈라졌다.**

## B4. 묶음마다 한 줄 — **폐기 (두 번째 시도)**

**버린 이유** — 갈라지진 않는데 **줄이 여덟**이라 붙여둘 수가 없었다.
→ 세 번째 모양(격자)으로 확정. 근거:

> 「메뉴를 가로로 배치하는 건 어때? 아래로 스크롤하면 대메뉴만 나오고
> 많이 올라가면 소메뉴 나오고」 (2026-08-07)
> 「PC는 생각보다 여백이 많은데 … 원래랑 비슷한데 정렬이 안 된 느낌이었어서」
> 「모바일은 지금이 좋아」
> 「PC에서는 마우스가 그리로 가면 소메뉴 나오게」

**격자여야 정렬이 맞는다** — 그냥 흘리면 폭이 제각각이라 줄이 어긋나 보이고,
그게 원장님이 걸리셨던 바로 그 느낌이다.
폭에 따라 한 줄에 2 · 3 · 4묶음 — **하나로 박으면 좁은 쪽은 넘치고 넓은
쪽은 오른쪽이 통째로 빈다.**

## B5. 머리말을 `sticky` 로 두기 — **폐기**

**버린 이유** — sticky 는 자리를 차지한 채 붙는다. 굴리는 도중에 머리말을
접으면 문서가 짧아지고 **읽던 자리가 위로 훅 튄다.** 손가락은 가만히 있는데
글이 움직이니 **그 자체로 고장처럼 느껴진다.**
→ `fixed` 로 띄우고 빈자리를 미리 잡아둔다.

## B6. 폰에서도 `:hover` 로 소메뉴 펴기 — **폐기**

**버린 이유** — 폰에서 `:hover` 는 **누른 뒤에 남는다.** 한 번 누르면 메뉴가
펴진 채로 안 접히고 다른 데를 눌러야 없어진다. 그러면 굴려서 접는 뜻이 없어진다.
→ `@media (hover: hover) and (pointer: fine)` 으로 가른다.

## B7. 시뮬레이션에 판단 규칙을 옮겨 적기 — **폐기**

**버린 이유** — `page.jsx` 의 규칙을 시뮬에 옮겨 적어 뒀는데 **그것 자체가
두 번 적는 일**이었다 (원칙 1 위반).
→ 시뮬이 `app/page.jsx` 를 직접 읽는다. 코드가 바뀌면 결과도 따라 바뀐다.

## B8. 감으로 고치기 — **금지**

> 순서: ① 무엇을 검사할지 정한다 → ② 시뮬레이션으로 실제 놓치는 것을 센다
> → ③ 그 결과로만 수정 순서를 정한다.
> **감으로 고치지 않는다. 시뮬레이션이 "놓쳤다"고 말한 것만 고친다.**

# C. 「하지 말 것」 제약 (전부)

| | 하지 말 것 | 까닭 |
|---|---|---|
| C1 | 막다른 배지·태그 (`<span className="btn">`) | 뜨는데 갈 곳이 없으면 실패 |

| C5 | 배지를 눌러 간 화면에서 다시 찾게 하기 | 배지가 일을 늘린 것이 된다 |

| C9 | 대시보드에서 저장하고 다른 화면으로 보내기 | 읽던 것이 흐려진다 (`router.push` 금지) |
| C10 | 빠른 처리 칸을 늘 펴두기 | 매일 여는 화면 맨 위를 입력칸이 차지한다 |
| C11 | 미납을 대시보드·메뉴 배지에 띄우기 | 원장님이 앱 범위를 그렇게 그으셨다 (B1) |

| C13 | 두 번째 실패에 알리기 | 흔해져서 정작 세 번째에 안 들린다 |

# D. 아직 결정 안 된 논점

## D1. 일정 4개 테이블 통합 여부 — **보류, 원장님 결정 필요**

`tasks` · `exam_periods` · `holidays` · `attendance.planned` 에 흩어져 있다.

→ 원장님 답 없음. 통합/유지 어느 쪽도 확정 아님.

## D2. 출결선생 · 결제선생 API 계약 조건 확인 — **미실행**

입금 전 서면으로 확인할 것으로 적혀 있으나 원장님 진행 여부 불명:
50만원의 성격(보증금 / 선불 충전금 / 발급 수수료) · 환불 조건 ·
충전금이면 소멸기한 · 계약 전 API 문서 열람 가능 여부 · 해지 시 데이터 반출.
(B2 에서 「권하지 않는다」 로 정리됐으므로 실질적으로는 닫힌 논점)

# E. 제안했으나 원장님 반응 없음 — **미확정**

아래는 **제가 제안했고 원장님이 답하지 않으신 것**이다. 확정된 것처럼
쓰지 말 것.

## E1. 학사일정 「나이스를 계속 볼 것인가」

`docs/지금-남은것.md` 에 「다시 볼 때 첫 물음」 으로 적어둔 것:
> 원본이 비는 학교가 절반이면, 받아오기를 붙들기보다 회차를 손으로 ·
> 홈페이지 붙여넣기로 채우고 나이스는 참고로만 두는 편이 낫다.

→ 원장님은 「포기야」 라고만 하셨다. **이 제안 자체에는 답이 없다.**

## E2. 대시보드에 시험대비 신호를 붙이는 것

`docs/영어시험-특징.md` 에 조사가 끝나 있고 「회차가 있어야 만들 수 있다」 고
적혀 있으나, **시험대비 페이지도 대시보드 연결도 원장님 지시가 없다.**

## E3. 「지금 남은것」 목록의 우선순위 제안

제가 「8번(권한 분리)이 제일 무겁고 10번(시험대비)이 제일 티가 납니다」 라고
말씀드렸으나 원장님이 고르지 않으셨다.

## E4. 캡처로 클래스카드 논의를 이어가는 방식

제가 제안했고 캡처 한 장을 주셨으나, **그 방식으로 계속할지에 대한 답은
없다.** 원장님은 「클로드가 직접 조작하는 것을 제1로 원한다」 고 하셨다.
