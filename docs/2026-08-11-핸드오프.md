## 1. 최종 목표

**학습 항목과 루틴을 원장님이 실제로 쓰실 수 있게 정리하는 것.**

- 학습 항목 = 행위 (정독, 문제풀기, 구두테스트…)
- 루틴 = 교재 한 권에서 그 행위들이 나오는 순서 (한 줄 = 한 수업 회차)
- 목적: 오늘 수업에서 「⟳ 루틴 다음」 한 번으로 그날 할 것과 숙제가 채워지게

**막힌 지점**: 원장님이 「엄두가 안 난다 · 머릿속 정리가 안 된다」 →
설계를 대신 해드리는 것이 아니라 **브레인스토밍으로 끌어내는 중**이었다.

## 2. 원장님이 요구하신 것과 까닭

| 요구 | 까닭 |
|---|---|
| 준비물(교재·클래스카드·노트)을 **아이에게** 표시 | 아이가 「뭘 펴야 해요?」 를 매번 물음 |

| 오늘 수업 화면 **중복 제거 · 순서 재배치** | 같은 학생 이름이 두 번, 등원 칸이 맨 아래 |
| **임시저장** | 수업 중 끊기면 적은 것이 날아감 |
| 전달사항에 **PDF·아무 파일**, **묶어 받기** | 한글·엑셀이 깨졌고, 파일마다 따로 받아야 했음 |
| 반 이름 시간 표시 정리 | 「19:30-22:00 화목 7:30~10:00」 로 두 번 나옴 |
| **클래스카드를 클로드가 직접 조작** | 「조작을 안 해보면 진짜 절대 알 수가 없어」 |

## 3. 확정된 결정

### 설계
- **루틴은 교재별** (`routine_steps.textbook_id`). 학생별이 아니다.
  학생의 진행은 `student_textbooks.routine_step` 이 기억한다.
- **영역(분류)과 준비물은 다른 축**이다. 「단어」 숙제를 클래스카드로도
  노트로도 한다 → 분류에 섞지 않고 `homework_items.tool` 로 따로 (0116).
- **준비물 목록은 못 박지 않는다.** datalist 로 고르거나 직접 적는다.
- **관리자 화면에만 「준비물」 이라는 낱말**, 아이 화면에는 아이콘+이름만
  (🃏 클래스카드). 접두어를 붙이는 순간 애매해진다 — 원장님 결정.
- **하위목록은 체크리스트형** (원장님 선택). 담당자·마감일 없음.
  `tasks.checklist`(한 줄에 하나) + `tasks.checklist_done`(체크된 줄의
  **글자 그대로** — 자리로 맞추면 순서 바꿀 때 엉뚱한 줄이 걸린다).
  되풀이 규칙(`todo_routines.checklist`)에 적으면 생기는 할일마다 복사.
- **집중도는 옛 `attitude` 칸 그대로**, 이름만 바뀜 (쌓인 별점 보존).
  이해도만 새 칸 (0118).
- **단원평가 적는 곳은 테스트 줄 하나**. 옛 「단원평가 상자」(unit_exams,
  0031)는 읽기 전용. 월간리포트는 두 쪽을 다 읽고 같은 날 같은 이름은
  하나로 센다.
- **반 이름 속 시간은 화면에서만 걷어낸다** (`lib/classLabel.js`).
  DB 는 안 고친다 — 반 관리 화면에서는 적힌 그대로 보여야 고치실 수 있다.
- **학사일정(나이스)은 멈춤.** 원장님: 「오류가 너무 심각해서 포기야」.
  까닭·되는 것·다시 볼 때 첫 물음은 `docs/지금-남은것.md` 「⏸️ 멈춘 것」.

## 4. 시도했다 실패한 것 — **다시 하지 말 것**

### 클래스카드를 클라우드 세션에서 조작 — **불가능**
세 겹으로 막혀 있다. 원장님이 「허용된 사이트」에 추가하셔도 안 됐다.

1. 이 세션에 **브라우저 도구가 없다** (ToolSearch 3회 확인)
2. `classcard.net` 이 **망 정책으로 차단** — 프록시 기록:
   `gateway answered 403 to CONNECT, host: www.classcard.net:443`
3. 뚫려도 **로그인**이 필요하고 원장님 비밀번호는 받으면 안 된다

「Claude in Chrome」 은 커넥터가 아니라 **크롬 확장**이다.
`ListConnectors` 결과에 Canva·Notion 둘뿐이고 크롬은 없다.
원장님 브라우저의 **사이드바 클로드**(Sonnet 5)는 잘 되고 있다 —
그쪽과 이쪽은 **다른 대화**라 서로 못 본다.

→ **로컬 세션에서는 될 가능성이 있다. 새 세션이 먼저 확인할 것.**

### 검사가 거짓으로 통과하던 것 (고침)
`SETUP_ALL.sql` 을 `build-setup-sql.mjs` 로 다시 안 찍어서 0115~0117 이

→ 하나도 못 이으면 아무것도 안 넣는다.

## 5. 미해결

### 클래스카드 — 아무것도 정해진 것이 없다
캡처 한 장에서 알아낸 구조만 있다 (`classcard.net/ClassMain/1769360`):

| 클래스카드 | 우리 앱 |
|---|---|
| 클래스 (NE능률 공통영어2) | 교재 |
| 세트 (Lesson 1.4) | 단원 |
| 카드 수 (3~29장) | 단원의 단어수/문항수 |

- 세트에 **「문장」/「단어」 배지**가 있다. 같은 Lesson 에 둘 다 있고 카드
  수가 다르다 (Lesson 2 영한단어 29장 vs 본문 문장 3~6장).
- 화면 상단 메뉴: 위치 이동 / 하이라이트·숨김 / **합치기** / 인쇄 / 제거
- **모르는 것**: 학습 모드가 몇 개고 각각 뭘 하는지, 「완료」 기준,
  선생님이 아이 결과를 보는 화면이 있는지, 문장/단어 세트가 모드가
  다른지. → 원장님이 **답 못 하신 질문**: 문장 세트와 단어 세트를 아이에게
  따로 내주시는가, 한 덩어리로 내주시는가.

### 루틴 설계 — 문법만 절반
원장님이 적어주신 것 그대로:

```
문법  정독+형광펜 / 교재로 문답노트 작성 / 강의듣고 문답노트 작성 /
      구두테스트 / 셀프테스트녹음 / 클래스카드 문법훈련 / 본교재 풀기 /
      실전 모의고사 풀기 / 워크북 풀기 / 채고세별

독해  저절로리딩 브릿지1·2·첫모의고사 / 자이스토리 기본·완성·실전 /
      모의고사 70분 연습 / 일관성있는 기준 영문법 / 영문법 문장훈련1 / 블록구문

영작  정독+형광펜 / 문제풀기 / 채고세별 / 오답 다시 풀기

클래스카드로 각 교재에 대한 추가학습
```

**여기서 찾아낸 것** (다음 세션이 이어받을 실마리):

1. **문법은 「행위」 를, 독해는 「교재 이름」 을 적으셨다.** 축이 달랐다.
   독해가 안 써진 것은 실력이 아니라 **교재 라인마다 하는 일이 달라서**다
   (원장님도 그렇게 쓰심). → 「독해 루틴」 을 짜려 하지 말고
   **「저절로리딩 브릿지1 루틴」** 을 짜야 한다. 앱 구조가 이미 그렇다.
2. **「채고세별」**(채점 후 고치고 세모별표)이 문법·영작 양쪽에 나온다 —
   학원 공통 규칙인데 **학습 항목에 없다.** 만들어야 한다.
3. **「정독+형광펜」** 도 문법·영작 공통인데, 지금 앱은 「문법 개념 정독 ·
   문답노트 정리」로 **둘을 하나에 뭉쳐놨다.** 따로 하시면 갈라야 한다.
4. 「실전 모의고사 풀기」(문법) 도 항목에 없다.

**원장님이 답 안 하신 질문**: 문법 10개를 한 단원에 **몇 번 수업**으로
나누시고, 그중 **집 / 학원**이 각각 무엇인가.

### 원장님이 눌러보셔야 끝나는 것
