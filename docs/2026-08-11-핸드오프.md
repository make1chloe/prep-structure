# 0. 대원칙 — 코드를 만지기 전에

> **원칙은 기능보다 우선한다.** (`docs/PRINCIPLES.md` 첫 줄)

## 원칙 1. 같은 값을 두 번 입력하지 않고, **두 벌로 출력하지도 않는다**

한 값은 **한 곳에서만 입력**하고 나머지는 참조한다. 출력도 같다 —
같은 정보를 그리는 코드가 두 벌이면 언젠가 한쪽만 고쳐지고,
**오류는 안 나고 화면만 조용히 어긋난다.**

- 같은 줄·문구는 한 벌의 컴포넌트/함수로 그린다
- 같은 계산은 `lib/` 의 한 함수가 하고 화면은 받아 그리기만 한다
- 이미 화면에 적힌 말을 같은 자리에서 반복하지 않는다

**이번 세션에서 이 원칙으로 잡은 것**: 반 이름 시간 두 번 표시,
오늘 수업 학생 이름 두 번, 단원평가 입력 두 곳, 진도 메모가 「메모」 로
따로 떨어져 있던 것.

## 원칙 2. 화면은 두 유형

| | 유형 A — 수업 중 | 유형 B — 관리 |
|---|---|---|
| 대상 | 오늘 수업, 출결·리포트 입력 | 교재·단원, 재원생, 반 |
| 최우선 | **이동 최소화** | **DB 구조의 정확성** |
| 규칙 | 한 화면에서 그날 일이 끝난다 · 토글로 나눠 본다 · 한 번의 탭 | 화면을 나눠도 된다 · 엑셀 업로드 · 전체선택→일괄처리 |

**10명이 넘으면 큰 표는 실제로 안 읽힌다** → 목록 + 펼치기 구조.

2. **규칙을 고치면 소비처를 전부 찾아** 하나하나 본다.

6. **한 곳으로 모은 규칙은 `check-dup.mjs` 의 ONE_PLACE 에 등록**

# 1. 최종 목표와 의도

## 앱 전체의 의도

노션으로 굴리던 학원 운영을 앱으로 옮긴 것. 핵심은
**「같은 것을 두 번 적지 않게 하는 것」** 과
**「수업 중에 화면을 옮기지 않게 하는 것」** 두 가지다.

## 지금 하려던 것 — 학습 항목과 루틴

- **학습 항목** = 행위 (정독, 문제풀기, 구두테스트…) — 교재·단원과 무관
- **루틴** = 교재 한 권에서 그 행위들이 나오는 순서 (한 줄 = 한 수업 회차)
- 목적: 오늘 수업에서 **「⟳ 루틴 다음」 한 번**으로 그날 할 것과 숙제가
  자동으로 채워지게. 누가 몇 번째인지는 앱이 기억한다

**막힌 지점**: 원장님이 「엄두가 안 난다 · 머릿속 정리가 안 된다 ·
너무 복잡하다」 → **설계를 대신 해드리는 것이 아니라 브레인스토밍으로
끌어내는 중**이었다. (이게 지금 상태다)

# 5. 확정된 설계 결정과 까닭

   노트로도 한다 → 분류에 섞지 않고 칸을 따로
3. **준비물 목록은 못 박지 않는다** — 고르거나 직접 적는다
4. **관리자 화면에만 「준비물」 이라는 낱말**, 아이 화면은 아이콘+이름만
   (🃏 클래스카드). 접두어를 붙이는 순간 애매해진다 — 원장님 결정
5. **하위목록은 체크리스트형** (원장님 선택). 담당자·마감일 없음.

6. **집중도 = 옛 attitude 칸** (쌓인 별점 보존). 이해도만 새 칸
7. **안 고른 평가는 줄 자체가 없다** — 빈 별을 보내지 않는다
8. **단원평가 적는 곳은 하나** (테스트 줄). 옛 상자는 읽기 전용
9. **반 이름 시간은 화면에서만 정리**, DB 는 그대로
10. **홈페이지 일정은 붙여넣기가 기본**, 주소는 부차
11. **학사일정(나이스)은 멈춤** — 까닭·되는 것·다시 볼 때 첫 물음은

→ 「최신 마이그레이션 번호가 합본에 있나」 검사 추가.
**마이그레이션을 더하면 `node scripts/build-setup-sql.mjs` 를 꼭 돌릴 것.**

## 6-4. 본보기 루틴이 빈 단계를 넣던 것 (고침)

학습 항목이 없을 때 누르면 **빈 3줄이 들어가고 단추는 사라졌다**
(steps.length > 0 이 되어서). 도우려다 일을 늘렸다.
→ 하나도 못 이으면 아무것도 안 넣는다.

## 6-5. 임시저장이 판을 접던 것 (고침)

`revalidatePath("/today")` 가 돌면 열어둔 판이 접힌다.
→ 임시저장일 때는 안 부른다 (`if (!form.draft)`).

## 6-6. 그 밖에 이번에 겪은 것

- `"use server"` 파일은 **async 함수만 export** 할 수 있다.
  상수·동기 함수는 별도 파일로 (`lib/noticeFile.js` 가 그래서 생겼다)
- 여러 줄 `import {` 안에 스크립트로 import 를 끼워 넣어 빌드가 깨졌다.
  `check-pages.sh` 3번 검사가 이걸 잡는다
- e2e 앱을 백그라운드로 띄울 때 `nohup ... &` 는 도구 호출이 끝나면
  죽는다. **Bash 도구의 `run_in_background`** 를 쓸 것

# 7. 미해결

## 7-1. 클래스카드 — 아무것도 정해진 것이 없다

캡처 한 장에서 알아낸 구조만 있다 (`classcard.net/ClassMain/1769360`):

| 클래스카드 | 우리 앱 |
|---|---|
| 클래스 (NE능률 공통영어2) | 교재 |
| 세트 (Lesson 1.4) | 단원 |
| 카드 수 (3~29장) | 단원의 단어수/문항수 |

- 세트에 **「문장」/「단어」 배지**. 같은 Lesson 에 둘 다 있고 카드 수가
  다르다 (Lesson 2 영한단어 29장 vs 본문 문장 3~6장)
- 상단 메뉴: 위치 이동 / 하이라이트·숨김 / **합치기** / 인쇄 / 제거
- **모르는 것**: 학습 모드가 몇 개고 각각 뭘 하는지 · 「완료」 기준 ·
  선생님이 아이 결과를 보는 화면이 있는지 · 문장/단어 세트가 모드가 다른지

**원장님이 답 안 하신 질문**: 문장 세트와 단어 세트를 아이에게 따로
내주시는가, 한 덩어리로 내주시는가.

## 7-2. 루틴 설계 — 문법만 절반

원장님이 적어주신 것 그대로:

```
문법  정독+형광펜 / 교재로 문답노트 작성 / 강의듣고 문답노트 작성 /
      구두테스트 / 셀프테스트녹음 / 클래스카드 문법훈련 / 본교재 풀기 /
      실전 모의고사 풀기 / 워크북 풀기 / 채고세별

독해  저절로리딩 브릿지1·2·첫모의고사 / 자이스토리 기본·완성·실전 /
      모의고사 70분 연습 / 일관성있는 기준 영문법 / 영문법 문장훈련1 / 블록구문

영작  정독+형광펜 / 문제풀기 / 채고세별 / 오답 다시 풀기

클래스카드로 각 교재에 대한 추가학습
```

**여기서 찾아낸 것 — 다음 세션이 이어받을 실마리**

1. **문법은 「행위」 를, 독해는 「교재 이름」 을 적으셨다.** 축이 달랐다.
   독해가 안 써진 것은 실력이 아니라 **교재 라인마다 하는 일이 달라서**다
   (원장님도 그렇게 쓰심). → 「독해 루틴」 을 짜려 하지 말고
   **「저절로리딩 브릿지1 루틴」** 을 짜야 한다. 앱 구조가 이미 그렇다
2. **「채고세별」**(채점 후 고치고 세모별표)이 문법·영작 양쪽에 나온다 —
   학원 공통 규칙인데 **학습 항목에 없다.** 만들어야 한다
3. **「정독+형광펜」** 도 공통인데 지금 앱은 「문법 개념 정독 · 문답노트
   정리」로 **둘을 하나에 뭉쳐놨다.** 따로 하시면 갈라야 한다
4. **「실전 모의고사 풀기」**(문법)도 항목에 없다
5. 클래스카드는 영역이 아니라 **교재에 붙는다** — 원장님이 「각 교재에
   대한 추가학습」 이라고 쓰셨다. 지금 앱 구조(단어 클래스카드 / 문법
   클래스카드로 나뉨)와 다르다

**원장님이 답 안 하신 질문**: 문법 10개를 한 단원에 **몇 번 수업**으로
나누시고, 그중 **집 / 학원**이 각각 무엇인가.
