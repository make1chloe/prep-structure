# 구글 캘린더 쌍방향 연동

원장님은 원래 구글 캘린더를 쓰고 계셨다. 앱과 연동이 안 돼서 앱에 달력을
따로 만든 것이다.

> **목표는 쌍방향이다.** (2026-08-05 원장님)
> 지금은 한 방향(앱 → 구글)까지 됐다. 이 문서는 나머지 반쪽을 할 때
> 처음부터 다시 생각하지 않기 위한 것이다.

---

## 1. 지금 어디까지 됐나 (2026-08-05, 0078)

**앱 → 구글, 읽기 전용 구독.**

```
앱 (Vercel)                          구글 캘린더
  /api/calendar?t=열쇠   ──읽어감──▶  「URL로 만들기」로 구독
     │
     └ calendar_feed(열쇠)  ← security definer, 열쇠 틀리면 빈 손
         일정(tasks kind=schedule, private 제외)
         시험(exam_periods, hidden 제외)
         휴강(holidays)
```

되는 것
- 앱에 넣은 일정이 구글에, 그리고 폰 캘린더에 따라온다
- 로그인이 필요 없다 — 구글이 아무 때나 부를 수 있다
- 열쇠를 새로 만들면 옛 주소가 그 자리에서 죽는다

안 되는 것
- **구글에서 넣은 일정이 앱으로 안 온다** ← 이 문서가 하려는 것
- 앱에서 고친 것이 구글에 **즉시** 반영되지 않는다 (구글이 몇 시간에 한 번 읽어감)
- 하루 종일 일정만 있다 (시간대 어긋남을 피하려고 일부러 그렇게 했다)

---

## 2. 왜 반쪽만 했나

읽기 전용 구독(.ics)은 **인증이 없다.** 주소만 있으면 된다.
쌍방향은 **구글 계정에 앱이 대신 쓰게 하는 것**이라 OAuth 가 있어야 한다.

| | 읽기 구독 (지금) | 쌍방향 (하려는 것) |
|---|---|---|
| 구글 쪽 준비 | 없음 | 클라우드 프로젝트 · OAuth 동의화면 · 심사 |
| 앱이 보관할 것 | 열쇠 하나 | 리프레시 토큰 (계정마다) |
| 실패하면 | 달력이 안 뜬다 | **원장님 개인 캘린더에 잘못 쓴다** |
| 되돌리기 | 주소 새로 만들기 | 구글 계정 설정에서 앱 권한 해제 |

세 번째 줄이 이걸 미룬 진짜 이유다. 남의 캘린더에 쓰는 일은 조용히 틀리면
안 된다.

---

## 3. 만드는 순서

### 3-1. 구글 쪽 (원장님이 한 번만)

1. [console.cloud.google.com](https://console.cloud.google.com) → 프로젝트 만들기
2. **Google Calendar API** 사용 설정
3. OAuth 동의 화면 — **외부**, 게시 상태는 **테스트** 로 두고 원장님 계정만
   테스트 사용자로 넣으면 심사 없이 쓸 수 있다
   (테스트 모드는 리프레시 토큰이 7일마다 만료된다. 계속 쓰려면 「프로덕션」
   으로 게시해야 하고 그러면 심사가 붙는다 — **여기가 제일 귀찮은 지점**)
4. 사용자 인증 정보 → OAuth 클라이언트 ID (웹) →
   승인된 리디렉션 URI 에 `https://<앱주소>/api/google/callback`
5. 클라이언트 ID · 시크릿을 앱 설정에 넣는다 (솔라피 열쇠와 같은 자리 ·
   `integrations` · 원장 계정만 읽음)

필요한 범위(scope)는 **`https://www.googleapis.com/auth/calendar.events`** 하나면
된다. `calendar` 전체를 달라고 하면 심사가 더 까다로워진다.

### 3-2. 앱 쪽

```
0079_google_oauth.sql
  google_accounts    profile_id · email · refresh_token(암호화) · calendar_id
  task_google_links  task_id ↔ google_event_id ↔ etag ↔ 마지막 동기 시각
  google_sync_state  syncToken (구글이 「지난번 이후 바뀐 것」 을 주는 열쇠)
```

- `/api/google/start` → 구글 동의 화면으로 보냄
- `/api/google/callback` → 코드를 리프레시 토큰으로 바꿔 저장
- `/api/google/push` → 앱에서 일정을 넣고·고치고·지울 때 구글에도 반영
- `/api/google/pull` → 구글에서 바뀐 것을 앱으로 (아래 §4)

### 3-3. 구글에서 앱으로 (제일 어려운 쪽)

두 가지 방법이 있다.

**(가) 주기적으로 물어보기** — `events.list` 에 `syncToken` 을 주면 지난번
이후 바뀐 것만 온다. 15분마다 부르면 된다. 단순하지만 서버가 필요하다
(Vercel Cron 으로 됨).

**(나) 구글이 알려주게 하기** — `events.watch` 로 웹훅을 걸면 바뀔 때
구글이 우리 주소를 두드린다. 빠르지만 **채널이 최대 한 달이라 계속 갱신**해야
하고, 알림에는 「뭐가 바뀌었는지」가 안 들어 있어서 결국 (가)를 또 불러야 한다.

**→ (가) 로 시작한다.** (나)는 「즉시」가 필요해지면 그때.

## 4. 미리 정해둘 것 (이게 이 문서의 핵심)

나중에 만들 때 여기서 막힌다. 답을 지금 적어둔다.

### 4-1. 누가 주인인가

**앱이 주인이다.** 나이스 학사일정을 붙일 때와 **같은 방향**으로 간다 (0075).

```
내 일정  ← 진짜. 화면과 계산은 전부 이것을 본다
구글 일정 ← 붙는 것. 다르면 알려주고, 반영은 원장님이 누른다
```

구글에서 온 것을 조용히 덮어쓰면, 시험 사흘 전에 일정이 어긋나 있어도 모른다.
0075 에서 이미 겪은 문제다 — **같은 실수를 두 번 하지 않는다.**

### 4-2. 구글에서 만든 일정은 어떻게 되나

`kind = 'schedule'`, `category = '기타'`, **`source = 'google'`** 로 들어온다.
앱에서 만든 것과 섞이되 **어디서 왔는지는 남는다.** 지우면 구글에서도 지울지
물어본다 (조용히 지우지 않는다).

### 4-3. 같은 일정이 두 번 생기는 것

제일 흔한 사고다. 앱 → 구글로 보낸 것이 → 다시 앱으로 돌아온다.

막는 법 — 구글 이벤트에 `extendedProperties.private.chloeTaskId` 를 심는다.
돌아온 것에 그 값이 있으면 **우리가 보낸 것**이므로 무시한다.

### 4-4. 시간대

구글은 시간이 있는 일정과 하루 종일 일정을 다르게 다룬다. 앱의 일정은
`due_on`(날짜) + `start_time`(선택) 이다.

- `start_time` 이 없으면 → 하루 종일 (`DTSTART;VALUE=DATE`)
- 있으면 → `Asia/Seoul` 을 **명시해서** 보낸다

시간대를 안 적으면 서버 시간대로 해석돼 하루씩 밀린다. 이 앱은 이미
`todaySeoul()` 로 한 번 겪었다.

### 4-5. 어느 캘린더에 쓰나

**「클로이영어」라는 캘린더를 앱이 하나 만들어서 거기에만 쓴다.**
원장님 기본 캘린더에 쓰면 개인 일정과 섞이고, 잘못 지웠을 때 되돌릴 수 없다.
켜고 끄기도 캘린더 단위로 되니 이쪽이 낫다.

### 4-6. 학생 개인정보

**지금 규칙을 그대로 유지한다** — 학생 이름은 캘린더에 안 담는다.
구글 캘린더는 원장님 개인 계정이고, 공유·백업 경로가 우리 손 밖이다.
「신송중 중2 1학기 기말」 까지가 한계선이다.

### 4-7. 토큰 보관

리프레시 토큰은 **솔라피 열쇠보다 위험하다** — 그것으로 캘린더를 지울 수 있다.

- `integrations` 와 같은 방식(원장 계정만 읽는 RLS)에 **더해**, DB 에 넣기 전에
  한 번 더 암호화한다 (열쇠는 Vercel 환경변수)
- 화면에는 절대 안 보여준다 (마스킹도 안 한다 — 아예 안 내려보낸다)
- 「연결 끊기」를 누르면 구글에 `revoke` 를 부르고 우리 것도 지운다

## 5. 가져다 쓸 것 (이미 만들어둔 조각)

| 필요한 것 | 이미 있는 것 |
|---|---|
| 열쇠를 안전하게 보관 | `integrations` + 원장 전용 RLS (솔라피 · 나이스 · Supabase 토큰) |
| 「내 것이 주인, 남의 것은 붙는 것」 | `0075_exam_owns_neis.sql` · `lib/exams.js` 의 `neisDiff`/`diffText` |
| 바뀐 것을 보여주고 원장님이 누르게 | 학교 일정 「내 것에 반영」 단추 (ScheduleBoard) |
| 칸이 없는 DB 에서 안 깨지기 | 어느 화면에나 있는 `PGRST204/42703` 물러서기 |
| 진짜 Postgres 로 확인 | `scripts/check-sql.sh` · `check-leak.sh` |
| 달력 그리기 | `app/tasks/CalendarBoard.jsx` (0077 때 만듦) |

## 6. 그때까지의 차선책

지금 방식(읽기 구독)으로도 **대부분은 된다.**

- 학원 일정을 폰에서 본다 ✔
- 개인 일정과 겹치는지 본다 ✔
- 구글에서 학원 일정을 **고치는 것**만 안 된다 ✘

원장님이 실제로 「구글에서 넣고 앱으로 오게」 하고 싶은 일이 얼마나 자주
생기는지를 한 달쯤 써보고 판단하는 게 낫다. 그 빈도가 낮으면 §3-1 의
OAuth 심사를 감수할 이유가 없다.
