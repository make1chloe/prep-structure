# 설계 원칙 (반드시 지킬 것)

이 문서의 원칙은 기능보다 우선한다. 새 화면을 만들기 전에 항상 여기부터 확인한다.

---

## 원칙 1. 같은 값을 두 번 입력하지 않는다 (Single Source of Truth)

하나의 값은 **한 곳에서만 입력**하고, 나머지 화면은 그 값을 **참조**한다.

### 지켜야 할 것

- 학생 이름·연락처는 `students`에만 있고, 리포트·출결·상담은 학생을 **연결**만 한다.
- 교재/단원은 `textbooks`·`textbook_units`에만 있고, 진도·리포트는 **선택**만 한다.
- 반의 요일·시간은 `classes`에만 있고, 출석부·시간표는 그걸 **읽어온다**.
- 학생별 진도는 한 번 기록하면, 데일리리포트·월말리포트·학부모 안내가 **같은 값을 재사용**한다.

### 하지 말아야 할 것

- 노션처럼 리포트에 교재명을 **텍스트로 다시 적기**
- 반 정보를 출석부 화면에서 **또 고르게 하기**
- 같은 숙제 항목을 화면마다 **다르게 나열하기** → 항목 마스터(`homework_items`) 하나만 사용

### 자동으로 흘러가야 하는 값

| 한 번 입력 | 자동으로 쓰이는 곳 |
|---|---|
| 학생 정보 | 출석부 · 리포트 · 상담 · 학부모 안내 · 로그인 계정 |
| 반 요일/시간 | 오늘 수업 목록 · 출석부 · 시간표 · 보강 안내 |
| 교재·단원 | 진도 입력 · 리포트 진도 문구 · 교재별 진도 현황 |
| 오늘 진도·숙제 | 데일리리포트 문구 · 다음 수업 숙제 · 월말 리포트 |
| 출결 기록 | 월별 출결 집계 · 결석/보강 안내 · 수납 계산 |
| 테스트 점수 | 리포트 문구 · 성적 추이 · 재시험 대상 추출 |

## 원칙 2. 화면은 두 유형으로 나눈다

모든 화면을 "이동 없이"로 만들면 오히려 복잡해진다. **용도에 따라 기준이 다르다.**

### 유형 A — 수업 중 화면 (이동 최소화가 최우선)

수업 시간에 선생님이 보는 화면. 화면을 옮길 여유가 없고, 한눈에 안 들어오면 못 쓴다.

**대상:** 오늘 수업 관리, 출석·리포트 입력

**규칙**
1. **한 화면에서 그날 일이 끝난다.** 페이지 이동·새 창 없음.
2. **한 번에 보이는 데이터를 줄인다.** 전체를 다 띄우지 않고 **토글로 나눠 본다.**
   - `등원예정` / `등원함` / `결석` / `보강` 상태별 토글
   - 기본은 "등원예정"만 보여주고, 처리한 학생은 목록에서 빠진다
3. **오늘·지금 기준으로 자동 필터.** 요일과 수업시간을 계산해 지금 수업할 반만 띄운다.
4. **정규수업과 보강을 함께** 본다. 보강 오는 학생도 오늘 등원자에 포함된다.
5. 클릭 수를 줄인다. 출석 체크는 **한 번의 탭**으로.

### 유형 B — 관리 화면 (DB 구조의 효율이 최우선)

데이터를 정비하는 화면. 수업 중에 쓰는 게 아니므로 **이동해도 된다.**

**대상:** 교재·단원, 재원생, 반(수업) 관리

**규칙**
1. **구조의 정확성이 우선.** 화면 편의를 위해 데이터를 중복시키지 않는다.
2. 필요하면 화면을 나눠도 된다. 대신 **엑셀 업로드**로 대량 입력을 지원한다.
3. 목록은 항상 **전체/일부 선택 → 수정·삭제·변경·이동**.

## 오늘 수업 화면 설계 (유형 A의 핵심)

### 전제: 10명이 넘으면 표는 못 쓴다

등원 학생이 10명 이상이면 학생 줄 × 항목 열의 큰 표는 **실제로 안 읽힌다.**
눈이 어디 있는지 놓치고 머릿속이 복잡해진다. 그래서 두 가지 모드로 나눈다.

| 모드 | 언제 | 형태 |
|---|---|---|
| **한 명 카드** (기본) | 학생이 등원할 때 | 화면에 **한 명만** 크게. 처리하면 다음 학생으로 |
| **명단 보기** | 전체 현황 확인 | 이름·상태만 있는 짧은 줄. 입력칸 없음 |

### 화면 구조

```
오늘 · 7월 25일 (금)        [등원예정 5] [등원 8] [결석 1] [보강 2]
────────────────────────────────────────────────────────────
                                                    ← 3 / 5 →
   홍길동   중2 · 금 5:00반                        [명단 보기]
   ─────────────────────────────────────────────
   출결    [정시] [지각] [결석] [보강]
   단어    [__] / 20        문장  [__] / 10
   숙제    ○ 독해   △ 워크북   ✕ 단어(온라인)   …
   진도    Unit 3  (지난 수업에서 이어짐)
   ─────────────────────────────────────────────
              [저장하고 다음 학생 →]
```

**핵심 동작**
1. **한 번에 한 명만.** 저장하면 자동으로 다음 학생으로 넘어간다.
2. **처리한 학생은 대기 목록에서 사라진다.** 남은 인원이 줄어드는 게 보인다.
3. 상단 **토글**로 상태별 인원만 확인 (등원예정 / 등원 / 결석 / 보강).
4. **명단 보기**로 전환하면 이름과 상태만 짧게 — 누가 안 왔는지 훑을 때만.
5. 진도·숙제는 **지난 수업 값이 미리 채워져** 있어 바뀐 것만 고친다.
6. 정규수업과 보강을 함께 본다. 보강 학생은 표시가 붙는다.

> 원칙: **선생님이 판단할 것을 화면이 대신 좁혀준다.**
> 전부 보여주고 고르게 하지 않는다.

## 원칙 3. 자동화는 데이터가 흐르게 만드는 것

발송이나 알림보다, **한 번 입력한 값이 다음 단계로 저절로 넘어가는 것**이 먼저다.

| 흐름 | 자동 처리 |
|---|---|
| 수업 입력 → 리포트 | 문구 자동 생성 (선생님은 확인만) |
| 오늘 숙제 → 다음 수업 | 미제출 항목이 다음 수업 화면에 자동 표시 |
| 출결 → 안내 | 결석 시 보강 안내 대상 자동 추출 |
| 테스트 미통과 → 재시험 | 재시험 대상 목록 자동 생성 |
| 진도 → 교재 종료 예상 | 남은 단원으로 교재 소진 시점 자동 계산 |

---

## 원칙 4. 그 밖의 확정 사항

1. 화면을 만들기 전에 **DB 속성을 나열하고 불필요한 것을 제거**한다.
2. 입력은 **엑셀 양식 다운로드 → 파일 업로드**를 기본으로 한다.
3. 모든 목록은 **전체/일부 선택 → 수정·삭제·변경·이동**이 가능해야 한다.
4. 학생 로그인 아이디는 `chloe + 전화 뒷자리 4`, 충돌 시 `-2`, `-3`.
   기본 비밀번호 `0000`, 첫 로그인 후 학생이 변경.
5. 노션의 수식·롤업·버튼은 저장하지 않고 앱 기능으로 대체한다.
6. 자주 바뀌는 항목(숙제 종류 등)은 컬럼이 아니라 **마스터 테이블**로 둔다.
7. UI 문구는 **선생님이 쓰는 말**로 쓴다. (설명용 단어를 화면에 그대로 쓰지 않기)
8. 여백보다 **한 화면에 담기는 정보량**을 우선한다.
