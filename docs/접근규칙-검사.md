# 접근 규칙 검사 — 처음 돌린 결과 (2026-09-02)

`node scripts/check-rls.mjs` · **읽기와 쓰기 둘 다 · 쓰기는 트랜잭션 안에서 하고 무조건 되돌린다**

```
통과 15 · 새는 곳 2
```

## ✅ 통과 15 — 격리는 잘 되어 있다

남의 판·성적·상담·수강료 **전부 0줄**. 쓰기도 전부 막힌다 —
자기 승격 · 남의 판 고치기 · 학부모가 수강료 고치기 · 학생이 남의 성적 넣기.
**학생이 자기 검사 결과(`daily_report_items`)를 고치는 것은 오류로 막힌다.**

## ❌ 새는 곳 2 — 같은 뿌리

```
학생이   마감 안 한 자기 판을 본다   70줄
학부모가 마감 안 한 판을 본다      122줄
```

**판 정책에 마감 술어가 없다:**
```sql
student_self_reports:  is_staff() OR (student_id IN (my_student_ids()) AND archived_at IS NULL)
                                                                        ↑ closed_at 이 없다
```

**사고 #7 이 실물로 확인됐다.** 계획이 「여전함 · **유일하게 밖으로 새는 사고**」라 적은 그것이다.

⚠️ **더 큰 것** — `closed_at` 이 **1,808줄 전부 비어 있다.**
마감 칸은 마이그레이션 **0169**(184개 중)로 최근에 생겼고 **한 번도 안 쓰였다.**
그래서 「마감 전 판을 본다」는 곧 **「만들자마자 다 보인다」**다.
수업 중에 적다 만 것도 학부모 화면에 그대로 있다.

→ **새 앱은 접근 규칙에 마감을 넣는다**(`closed_at is not null`).
→ **그리고 마감을 안 하면 아이 화면이 「아직 정리 중이에요」로 서야 한다**(계획 ⑮ 3번) —
   안 그러면 **마감 안 한 날과 진짜 없는 날이 아이에게 똑같아 보인다.**

## ⚠️ 내 검사가 틀렸던 것 — 남겨 둔다

처음엔 **「학생이 자기 성적을 고친다 — 1줄」**이 나왔다. **사고가 아니었다.**

```sql
score_own_update:  source = 'form' AND 자기 것
```

**아이가 넣은 것(`source='form'`)만** 고칠 수 있다. 원장님이 넣은 것은 못 고친다.
원장님 말씀 그대로다 — 「성적과 오답번호는 학생이 넣는 거고, 나는 확인 후 수정하는 거야」.

→ 검사를 **「원장님이 넣은 성적을 고치는가」**로 고쳤다. **0줄 ✅**
→ ⚠️ **검사를 쓸 때 「막아야 하는 것」과 「해도 되는 것」을 안 가르면, 멀쩡한 것을 사고로 읽는다.**

---

## 새 앱이 그대로 가져갈 것

| | |
|---|---|
| `is_staff()` · `my_student_ids()` · `score_visible()` | **함수로 뺀 것이 옳다.** 정책마다 풀어 쓰면 한 곳이 빠진다 |
| `source='form'` 로 「아이가 넣은 것」을 가르는 방식 | 진도의 「마지막에 누가」(표 4-8)와 **같은 모양** |
| 쓰기 정책을 `qual` 과 `with_check` **둘 다** 거는 것 | 하나만 걸면 옮겨 놓기(UPDATE ... SET student_id) 가 뚫린다 |

# 전수 검사 — 표 85개를 다 훑었다 (2026-09-02)

```

```

## 처음엔 「보이는 자리 34건」이 나왔다 — 대부분 정상이었다

| 표 | 보이는 것 | 판정 |
|---|---|---|
| `students` 1/24 · `profiles` 1/46 · `classes` 1~2/9 | **자기 것만** | ✅ 정상 |
| `daily_report_items` 121/4150 · `score_items` 13/122 | **자기 것만** | ✅ 정상 |
| `textbooks` 162 · `textbook_units` 7,383 · `homework_items` 64 · `schools` 11 | **이름뿐** | ✅ 보여도 됨 |
| `app_assets` · `holidays` · `screen_layouts` · `screen_notes` · `notices` | 설정·공지 | ✅ 보여도 됨 |
| **`integrations` 1/15** | 보이는 1줄은 **`schedule`, 길이 21자, 열쇠 없음** | ✅ 확인함 |

⚠️ **`integrations` 는 반드시 눈으로 봐야 하는 자리다** — 열쇠가 든 줄이 15개 중 14개인데
학생에게는 **열쇠 없는 1줄만** 보인다. 만약 여기가 뚫렸으면 **나이스·유튜브·앤트로픽 열쇠가 통째로 샌다.**

## ⚠️ 새지는 않지만 줄일 것 2가지

```
exam_periods   학교 8곳 58줄 전부가 학생·학부모에게 보인다
tasks          학사일정 47줄 (전부 private=false, kind=schedule)
               「인천해송고등학교 동아리활동」처럼 **다른 학교 것도** 보인다
```

개인정보는 아니다. **원장님 개인 할 일은 안 보인다**(private 걸러짐).
→ 새 앱에서는 **자기 학교 것만** 보이게 좁힌다.

## ❌ 진짜 새는 것은 여전히 하나 — 마감

전수로 훑어도 **새는 자리는 「마감 안 한 판」 뿐**이다(70줄 · 122줄).
격리(누구 것인가)는 **165개 정책이 제대로 하고 있다.** 빠진 것은 **「언제부터 보이나」** 하나다.

## 검사에 못 박아 둔 것 — 다음에 돌릴 사람을 위해

`scripts/check-rls-all.mjs` 안에 **표마다 「보여도 되는가」를 적어 두었다.**
이걸 안 적으면 **멀쩡한 것을 사고로 읽는다.** 실제로 그럴 뻔했다(`scores` 의 `source='form'`).
**새 표를 만들면 이 목록에 한 줄을 더해야 하고, 안 더하면 검사가 「새는 자리」로 세운다** — 그게 맞다.
