**빌드**: `npx next build --webpack` — **통과**(2026-09-03 실측, exit 0). 화면 10개가 다 선다.

**다음 할 일** — 순서가 이미 정해져 있다(`docs/원장님-정하실-것.md` 「지을 것」).
1·2는 지었고 **3번 「등원·하원 알림을 어머니께」가 다음**이다. 4~9는 그 뒤. 자세한 것은 11절.

**절대 하면 안 되는 것 다섯**

1. **`main` 브랜치에 푸시하지 마라.** `main` = 지금 학원이 쓰는 옛 앱이고 푸시가 곧 배포다(`대전제-2`).
2. **마이그레이션에서 `auth.` · `storage.` · `public.` 을 건드리지 마라.** 건드리면 **평일 저녁에 옛 앱이 반쯤 죽고**, 도메인을 되돌려도 안 돌아온다. `scripts/check-v2only.mjs` 가 잡는다. 예외는 `9000_switch_day.sql`·`9001_purge_public.sql` 둘뿐이고 **그 둘은 평소에 돌리지 않는다.**
3. **권한 기본값을 코드에 박지 마라.** `?? true` · `|| true` 로 슬쩍 넣는 것도 안 된다 — 원장님이 끄신 자리가 되살아나고 **아무 오류도 안 난다.** 원장님 말: 「그런 권한기본값을 니가 미리 정해서 코드에 박아 놓는 게 아니라 내가 웹상에서 설정 할 수 있게 해」
4. **검사를 통과시키려고 앱 코드를 고치지 마라.** 테스트 전용 뒷문도 안 된다. 검사가 빨간 것은 앱이 틀렸다는 뜻이다.
5. **재원생·학부모의 진짜 비밀번호를 건드리지 마라.** 로그인 확인은 `zz_시험_` 계정 **다섯**으로만 한다(`대전제-12`) — **원장 · 강사 · 학생 · 학부모 · 남의아이**(아직 학생과 안 이어진 계정). `0004_fixture.sql`에 있다.

## 2. 지켜야 할 규칙

`docs/규칙.md`가 원본이고 여기는 첫날 필요한 것만 옮겼다. **어긋난 곳을 말할 때 번호로 가리킨다.**

### 대전제 — 움직이지 않는 것

| 번호 | 규칙 |
|---|---|
| **대전제-0** | **안 되는 것·모르는 것을 정확히 말한다. 근거 없는 낙관 금지.** 숫자는 센 것만 쓰고 어디서 셌는지 밝힌다. 구현 못 하는 것을 그리지 않는다. **모든 것에 앞선다** |
| **대전제-1** | 전환일까지 **옛 앱이 진실**이다. 새 앱 값은 이관으로만. 예외 셋 — `fixture`(안 지움) · `rehearsal`(재적재가 먼저 지움) · `excel`(재적재가 안 지움) |
| **대전제-2** | **옛 앱은 동결.** `main`에 안 푸시한다 |
| **대전제-3** | 둘 중에 고를 때는 **원장 일이 적어지는 쪽.** 기능이 많은 쪽도, 유연한 쪽도 아니다 |
| **대전제-4** | **판단은 `lib/` 한 곳.** 화면은 받아 그리기만. 같은 판단이 있는지 **grep 먼저** |
| **대전제-5** | **세어 나오는 값은 저장하지 않는다** — 회차·청구액·성취도 %·진도율·출석률·통과 여부 |
| **대전제-6** | **지우지 않는다.** 상태로 내린다(끝냄·중단·절판·보관·`retired`) |
| **대전제-7** | **밖으로 나가는 길은 `lib/notify.js` 한 곳에서만** |
| **대전제-8** | 화면을 고르는 기준 셋 — ① 한눈에 보이나 ② 빠른가 ③ 클릭이 쓸데없이 늘지 않나. 가르는 물음은 「몇 번 여나」가 아니라 **「안 열면 일이 되나」** |
| **대전제-9** | **`position:fixed` 스크롤 잠금 · `history.pushState` 닫기 · `createPortal` 안 쓴다** |
| **대전제-10** | **닫는 길은 언제나 화면 안에.** 저장 중이라고 닫기를 잠그지 않는다. **`alert`/`confirm` 안 쓴다** |
| **대전제-11** | **옛 앱 화면을 베끼지 않는다.** 메뉴·배치는 백지에서 (데이터 구조는 다르다 — 엑셀이 뼈대다) |
| **대전제-12** | 재원생·학부모 **진짜 비밀번호는 전환일까지 한 번도 안 건드린다** |

### 원칙

| 번호 | 규칙 |
|---|---|
| **원칙-1** | **같은 값을 두 번 입력하거나 두 벌로 출력하지 않는다** |
| **원칙-4** | **고치기 전에 전체 정합성을 검토한다.** 예외가 세 번째로 필요해지면 설계를 다시 본다 |
| **원칙-5** | 세어 나오는 값은 저장하지 않는다 (= 대전제-5, 다른 번호로도 부른다) |

⚠️ **원칙 2·3은 이 프로젝트 문서에 없다.** 옛 앱 문서에 있었을 수 있으나 **확인 안 됨.**

### 원장님 작업 규칙 여섯 — 사람과 일하는 법

1. **근거 없는 낙관 금지.** 모르면 「모릅니다」라고 말한다. 「될 겁니다」는 안 된다.
2. **설명은 짧게, 결론 먼저.** 여러 번 요청받은 것이다.
3. **목록에 없는 건 건드리지 마.** 부탁받은 것만 고친다.
4. **「일부러 어기는 줄을 하나씩 넣어서 검사가 진짜 빨개지는지 보여줘. 빨개지는 걸 못 보여주면 안 고쳐진 거야.」** 검사를 만들거나 고쳤으면 **깨지는 것을 실제로 보여야** 끝난 것이다. `폰-5`가 같은 말이다.
5. **권한 기본값을 코드에 박지 않는다** — 원장님이 웹에서 정한다.
6. **앱 코드를 검사 통과용으로 고치지 않는다.**

**PR은 만들지 않는다** — 작업 브랜치와 `v2` 둘 다에 바로 푸시한다(원장님 허락).
⚠️ 관행과 다르다는 것을 알고 하는 것이다. 되돌릴 안전망은 **검사 58종 + 빌드**뿐이므로 **푸시 전에 반드시 돌린다.**

### 폰 규칙 — 이미 값을 치른 것

| 번호 | 규칙 |
|---|---|
| **폰-1** | 입력 요소 글씨 **16px 이상** — 인라인 `fontSize`도. ⚠️ **`(pointer:coarse)`로 가른다** (폭이 아니라 기계로 — `max-width:760px`로 걸었더니 아이패드 768px이 빠졌다) |
| **폰-2** | 열릴 때 **`autoFocus` 안 건다** (키보드가 튀어 올라 화면이 뛴다) |
| **폰-3** | sticky를 넣는 자리는 **조상에 `overflow:hidden`이 없는지** 먼저 본다 — 있으면 **오류 없이 그냥 안 붙는다** |
| **폰-5** | **글자로 훑는 검사는 헛짚고 헛통과한다** — ① 주석을 먼저 지운다(줄 끝 `//` 포함) ② 앞뒤를 정확히 문다 ③ 같은 조건 블록이 여럿이면 합집합. **일부러 어기는 본보기를 두고 검사가 잡는지 확인한다** |
| **폰-6** | `visualViewport`로 저장줄 높이 · `env(safe-area-inset-bottom)` + `viewportFit:"cover"` |
| **폰-9** | **클래스 이름 겹침 금지**(`.v`·`.q`·`.open`으로 세 번 터졌다) · flex/grid 자식에 **`min-width:0`** · 몸통에 **`word-break:keep-all`** · grid는 **`minmax(0,1fr)`** · **글씨를 `opacity`로 흐리게 금지**(색으로 말한다). ⚠️ **아이콘은 예외** — 투명도가 곧 뜻이다(원장님 9/3: 「그건 **글씨** 얘기고 아이콘은 괜찮아. **낮은 투명도 자체가 정보**인 거야」) |

한글 줄바꿈은 기본값이 아무 데서나 끊어 **한 글자씩 세로로 쌓인다.** `word-break:keep-all`이 그것을 막는다.

## 3. 구조

### 브랜치와 배포

| | |
|---|---|
| 레포 | GitHub `make1chloe/prep-structure` |
| **`main`** | **지금 학원이 쓰는 옛 앱.** Vercel Production → `chloe-english.vercel.app`. **동결** |
| **`v2`** | **새 앱.** 고아 브랜치(`git checkout --orphan v2`)라 `main`과 파일이 하나도 안 섞인다. 푸시하면 Vercel **Preview** 배포가 선다 |
| Vercel 프로젝트 | `dashboard-claude` (하나다 — 새로 만들지 않았다) |
| 전환하는 날 | Vercel Settings → Git → **Production Branch를 `main` ▸ `v2`로.** 주소가 안 바뀌므로 **재설치가 필요 없다** |

주소를 물려받는 이 방식을 고른 까닭: 도메인을 새로 사면 **폰에 깐 앱을 전원이 다시 깔아야** 한다.
브랜치만 바꾸면 주소가 그대로라 그 일이 통째로 없어진다. 드는 돈도 0원이다.

⚠️ **환경변수는 저장만으론 안 박힌다.** 그 브랜치를 **다시 배포**해야 들어간다.
없으면 화면이 스스로 말한다 — 「⚠️ 설정을 못 읽었습니다 — DATABASE_URL 이 없다 (Vercel 환경변수)」.

### Supabase

**옛 앱과 같은 프로젝트**를 쓰고 스키마만 `v2`로 따로 판다. 새 프로젝트를 만들지 않은 까닭:
새로 만들면 `auth.users`가 안 따라와 **학생·학부모 전원 계정을 재발급**해야 하고, Storage 버킷을 통째로 옮겨야 한다.
같은 프로젝트면 이관이 `INSERT ... SELECT` 한 벌이고 **계정·파일·푸시 구독이 손대지 않은 채로 산다.**

`Project Settings → API → Exposed schemas`에 **`v2`를 더했다**(9/3). 빼는 게 아니라 더하는 것이라 옛 앱은 그대로 산다.
안 돼 있으면 화면이 「앱 설정이 아직 덜 됐습니다 (v2 스키마 노출 안 됨)」라고 말한다.

### ⚠️ `v2` 밖에 있는 것 — 전환일까지 손대지 않는다

같은 프로젝트를 쓰는 값이다. **`v2`로 격리되지 않는 것**:

`auth.users`와 거기 붙은 트리거 · Storage 버킷과 정책 · `public`의 함수·타입 **이름** ·
PostgREST 노출 스키마 설정 · Realtime publication · DB 역할.

**규칙 셋**
1. **`auth.users`에 새 트리거를 붙이지 않는다.** v2 트리거가 v2 제약에 걸리면 `INSERT` 자체가 실패해 **옛 앱의 계정 발급이 그 자리에서 멈춘다** — 학생을 등록하는 순간 계정이 저절로 발급되므로 **신규 상담 도중 등록 전환이 끊긴다.**
2. **`public`에 함수·타입을 만들지 않는다.** `create or replace`가 옛 앱의 같은 이름 함수를 덮으면 옛 앱이 조용히 반쯤 죽는다.
3. **Storage 정책을 지금 쓰지 않는다.** 새 정책 SQL은 `9000_switch_day.sql`에 모아 두었다.

**이 셋은 도메인 원복으로 못 되돌린다.** 전환일 사고가 아니라 **공사 중 평일 저녁 사고**다.

### RLS 모델

- 모든 `v2` 표에 **`force row level security`**. 없으면 **표 주인이 규칙을 그냥 지나간다**(`0077`이 그 사고를 고쳤다).
- 정책은 `v2.is_staff()` · `v2.my_students()` · `v2.can(key)` 세 함수로 판단한다. **정책 안에서 다시 판단하지 않는다**(원칙-1).
- **`auth.uid() is null`이면 통과시킨다.** 검사와 마이그레이션이 로그인 없이 도는 길이다. 트리거도 그때는 그냥 통과한다.
- **트리거는 superuser에게도 걸린다** — 그래서 잠금을 트리거로 짠다.
- **정책과 GRANT는 짝이다.** 하나만 있으면 안 된다 — `check-grants`가 본다.

### 화면마다 알아야 할 것

**s1 오늘 수업** — 하루가 셋으로 나뉜다. **① 숙제 검사가 방아쇠**이고 ②오늘 학습·③오늘 숙제는 **저절로 깔린다**(확정-⑨).
②③은 **한 카드에 좌우**로 붙인다(폰은 위아래) — 같은 교재 같은 회차라 한 덩어리로 보여야 한다(확정-⑨a).
회차 세그먼트는 학습·숙제 **각각 하나씩** 화면에 그대로 두고, **교재마다 메모 둘**(학습 한 줄·숙제 한 줄)을 둔다.
⚠️ **①이 안 끝나면 ②가 안 깔린다는 뜻이 아니다** — 아이가 안 해왔어도(✕) 「다음 회차」 대신 **「그 단원 다시」**가 깔린다.
안 되는 것: 늦귀가 **보내기가 이 화면에 없다.** AI 브리핑(키워드 → 살 붙이기)은 **부르는 자리가 아직 없다.**
화면이 **0.7초**다(목표 0.5초).

**s2 조절** — **교재마다 · 갯수로**(확정-㉓). 화면에 뜨는 것은 **개수가 아니라 문항·쪽의 합계**다 —
같은 「3개」가 교재마다 **6문항에서 178문항까지** 간다(37권 실측). 30배다.
⚠️ **「기준(대단원/소단원)」 세그를 여기서 뺐다**(9/3) — 11 학생 루틴에 같은 값이 있어 두 벌이었다. 12절 참고.

**s2b 진도 체크** — **아이가 자기 교재 진도를 찍는다.** 설정으로 켜고 끈다(확정-㊶).
날짜 자동 만료는 **안 쓴다**(원장님: 「날짜가 아니라 그 관리화면에서 on off 하고 싶어」) — 대신 켜져 있는 동안
대시보드 맨 위에 **「진도 체크가 N일째 열려 있습니다 · 끄기」** 한 줄이 선다. 「켠 날짜」는 그래서 필수다.
아이가 찍은 줄은 **「확인 기다리는 중」**으로 따로 서고, **원장이 찍은 줄은 아이가 못 덮는다.**
❗이의는 **진도를 안 바꾼다** — 원장님이 누르는 순간에만 바뀐다.
⚠️ **아이가 틀리게 찍는 것을 앱이 못 잡는다.** 그래서 「확인 기다리는 중」이 필수다.

**s6 내 할 일 (보드)** — **바깥 축은 「할 일 종류」**다(자료 만들기·인쇄·배부·출제·재시험·성적·되풀이).
학교가 아니다 — 원장님은 **같은 일을 몰아서** 하신다(인쇄는 앉은 김에 92장). 학교로 좁힐 땐 **거르개 한 줄.**
내신은 **파이프라인이 아니다**(확정-㉟) — 「남은 것」 목록이고 **마감만 있고 순서는 없다.**
**자료 하나 안에서만** 순서가 있다(만들기 → 인쇄 → 배부 → 풀이 → 채점, 클래스카드는 인쇄가 없어 네 걸음).
**보드 생김새는 노션 보드다**(원장님 9/3) — 12절.
재활용은 고르는 것이 아니라 **「만들기가 체크된 채로 서는 것」**(확정-㊵). 개정판이면 체크하지 않는다.

**s6c 표 — 표 하나에 보기 둘** — **9/3 원장님 결정.** 12절이 전부다.

**s7 학생 화면** — 아이 화면은 **등원 뒤에 열린다**(원장님 9/3: 「출석하면 바로」). ⚠️ **학부모는 그대로 마감 뒤.**
카드 차례를 아이가 바꿀 수 있고 **사람마다 저장**된다(끌기 + ▲▼ — 폰에서 끌기는 스크롤과 부딪혀 자주 실패한다).
끝낸 것은 아래로 접고 개수만 띄운다. **빈 카드는 아이·학부모 화면에서만 숨긴다** — 원장 화면에서는 빈 것도 보인다(빠뜨린 것을 잡으려고).
⚠️ **마감해야 「없음」으로 굳는다.** 마감 전에는 「아직 정리 중이에요」 — 안 그러면 마감 안 한 날과 진짜 없는 날이 아이에게 똑같아 보인다.

**s10 발송** — **탭을 만들지 않는다**(속도-1). 급한 순서로 한 화면에 세우고 접기로 줄인다 — **접기는 다시 조회하지 않는다.**
고르고 · 한 번에 · 예약(오늘 21:00 · 내일 9:00 · 직접)(확정-㉕).
⚠️ 늦귀가 사유는 **이 화면에서 만들지 않는다** — 12절.

**s12 일정** — **회차는 수강료가 아니라 「8회를 채웠나」**다. 못 채우면 **보강을 잡는다.**
휴강은 회차에서 **빠지고** 결석은 **안 빠진다.** 8회가 모든 반의 기준이고 **보강일은 학생마다 따로** 잡는다.
⚠️ **보강 시각을 앱이 제안하지 않는다**(확정-㉔) — 원장님: 「니가 시간이랑 일정을 잡으면 내가 고칠 수가 없잖아」.
달력을 열어 아무 날이나 고르고 시각도 직접 적는다. 빈 자리 셈은 **보여만 주고 막지 않는다.**

**s12b 학사일정 받아오기** — 시험은 두 갈래다(확정-㊲). **전국**(수능·학평·모의)은 **학교를 안 붙인다** —
나이스가 학교마다 한 줄씩 내려주므로 학교 5곳이면 같은 학평이 5줄로 들어온다. **받아올 때 이름으로 갈래를 판정**하고
그 **낱말 목록을 원장님이 고칠 수 있게** 한다. 받아온 것을 **덮지 않는다**(출처 + 출처 열쇠).
⚠️ **영어 시험일은 안 온다** — 학교가 나이스에 안 올린다. 한 줄 손으로 넣으면 전날 등원·안내·마감이 한꺼번에 선다.

**s13 수강료** — 가볍다. **금액 넣고 받은 날 체크가 전부**(원장님: 「아직 결제는 중요한 내용이 아니다」).
정규는 **월정액**이고 회차와 무관하다. **특강만 회차만큼** 받는다. 금액이 비면 **0원이 아니라 「아직 안 적음」**이다.

**s14 학생 — 재원생·성장** — ⚠️ **화면이 아예 없다.** 원장님이 「**재원생 출결정보**에 날짜별 기록」이라 하셨는데
새 앱에는 재원생 화면 자체가 없다. 지금 하원은 **아이 달력**에 뜨고 원장님은 오늘 화면에서 고치신다.
재원생 화면을 세울 때 그 표를 그대로 옮겨 붙이면 된다.

**s16 성적** — 아이가 넣고 원장님이 확인한다. 표(`v2.score`·`v2.score_wrong`)는 있고 **화면이 없다.**
⚠️ **성장 리포트 자동 문장은 자료가 차기 전에 만들지 않는다** — 반쯤 넣으면 「평균 수준을 유지하고 있습니다」가 근거 없이 나간다.

**s19 영상** — **앱 안에서 본다.** 링크를 눌러 유튜브로 튕겨 나가지 않는다.
**재생 위치를 주기적으로 남겨** 「어디까지 · 몇 %」를 안다. 끝까지 끌어다 놓고 「다 봤다」를 누르는 길을 막는다 —
**실제로 지나간 구간**을 세고 건너뛴 구간은 안 센다(`v2.video_seen`).
⚠️ **대략치다.** 임베드 막힌 영상은 앱 안에서 못 틀고, 「틀어놓고 딴짓」은 못 잡는다. **아이를 판단할 숫자가 아니다.**

**s20 자료함** — **30장** · 사진은 긴 변 **1600px**(폰 사진 30장 원본은 150MB가 넘는다) · pdf·문서는 안 줄인다.
분류는 **올린 아이에게서 저절로** 붙고 원장님은 **갈래만** 고른다. ⚠️ **형제가 있으면 누구 것인지 먼저 묻는다** —
안 물으면 형 학교 자료가 동생 칸에 들어간다. 받은 것은 **원장님만** 본다.
⚠️ **아이가 아무거나 올리는 것을 앱이 못 막는다.** 실행되는 파일은 아예 안 받는다.
⚠️ **Storage 버킷·정책은 `v2` 밖이다** — 새 정책 SQL은 `9000`에 있다. 공사 중에 건드리면 **옛 앱의 숙제 사진이 그날 저녁부터 안 올라간다.**

## 7. 검사

### 돌리는 법

```bash
bash scripts/check-all.sh
```

`scripts/check-*.mjs`를 **훑어서** 돈다 — 새 검사를 만들면 **저절로 들어온다.**
⚠️ 옛 앱은 검사 목록이 손으로 나열돼 있어 **등록을 빠뜨리면 안 돌았다.** 그 함정을 없앤 것이다.
**빌드도 검사다** — 마지막에 `npx next build --webpack`이 돈다. 검사만 보려면 `SKIP_BUILD=1`.

⚠️ **`npm run check`를 쓰지 마라** — `scripts/check-pages.sh`를 부르는데 **`v2`에 그 파일이 없다**(`main`의 것이다).
`package.json`이 아직 안 고쳐져 있다. **`bash scripts/check-all.sh`를 직접 부른다.**

### ⚠️ 지금 빨간 검사 하나 — `check-screen-home`

```
❌ 문 「todos」 직렬 10단 (상한 5 +아는 초과 4)
   · 문마다 조회 — frame 2 · waiting 4 · sessions 3 · books 3 · todos 8
■ 대시보드 검사 109건 · 실패 1 · 못 고치는 것 2건
```

**무엇인가** — 대시보드의 속도 상한은 **조회 20 · 직렬 5단**이다(`속도-상한`). 「내 할 일」 카드는
`lib/todo.js`의 `myTodos()`가 조회 **여덟**을 차례로 물어서, 맨 위 줄(`frame` 2)을 기다리는 것까지 합쳐 **10단**이다.
검사에 `아는_초과 = { todos: 4 }`가 적혀 있어 **9단까지는 봐준다** — 그 값은 「실측 9단」으로 잡은 것이고 **지금은 10단**이다.

**두 번 돌려도 같다**(`frame 2 · todos 8`). 데이터가 흔들려서 나는 것이 아니다.

**고치는 법은 하나뿐이다** — 검사가 스스로 말한다: **「화면에서 다시 짜지 말고 lib을 고쳐라.」**
`myTodos()`가 여섯~여덟을 **차례로** 묻는 것을 병렬로 묶거나 조회를 합쳐야 한다.

⚠️ **하지 말 것 둘.** ① `아는_초과`를 5로 올려 초록을 만드는 것 — **검사를 고쳐 통과시키는 것**이다.
② 화면에서 카드를 빼는 것 — 검사 주석이 「막으면 배지를 빼는 쪽으로 도망가게 된다」고 미리 적어 두었다.

⚠️ **마이그레이션을 고치면 다시 돌려야 한다** — sha가 안 맞으면 검사가 빨개진다. DB가 파일보다 낡은 것을 그렇게 잡는다.

### 「빨개지는 것 확인」 — 이 프로젝트의 검사 문화

원장님 규칙 4번이다. 검사를 만들거나 고쳤으면 **일부러 어기는 줄을 넣어 빨개지는 것을 실제로 보여야** 끝난 것이다.
코드 안에 그 흔적이 남아 있다:

- `scripts/check-attend.mjs:471` — 「⚠️ `\w`를 쓰지 마라 — 한글 이름(`via:"웹훅"`)을 못 잡는다. **일부러 깨 보고 안 잡히는 것을 봤다**」
- `scripts/check-arrival.mjs:188` — 「검사가 통과한다 — **실제로 일부러 바꿔 보고 안 잡히는 것을 봤다**」
- `scripts/_layout-fixture.html` — **레이아웃 검사가 잡는지 보려고 일부러 어겨 둔 본보기 파일**
- `PERM_BREAK_SQL` — 권한 검사가 **일부러 권한을 깨 보는** 환경변수

**글자로 훑는 검사를 쓸 때 조심할 것**(`폰-5`):
① **주석을 먼저 지운다**(줄 끝 `//`도) ② **찾는 낱말의 앞뒤를 정확히 문다**(`1700px`이 `700px`으로 걸리지 않게)
③ 같은 조건 블록이 여럿이면 **합집합**으로 본다.
⚠️ **JS의 `\b`는 한글 앞에서 절대 안 맞는다** — `(?<![\w가-힣])`를 쓴다. 실제로 이것 때문에 검사가 헛통과했다.
⚠️ **부르기만 보지 말고 답을 쓰는지 봐라** — `blockedBy()`를 부르는 줄만 찾으면, 부르고 결과를 버리는 코드가 통과한다.

## 10. 첫 배포(전환) 체크리스트

⚠️ **이것은 「전환」이 아니라 「첫 배포」다.** 계정을 실제로 세어 보면 그렇다.

**옛 앱(`public`) — 2026-09-02 실측** (테스트 계정 제외):

| | 계정 | 한 번이라도 로그인 | 알림 켠 기기 |
|---|---|---|---|
| 원장 | 1 | 1 | 2 |
| 강사 | 1 | 1 | 0 |
| 학생 | 21 | **3** | **1** |
| **학부모** | **20** | **0** | **0** |

**학부모는 한 명도 앱을 연 적이 없다.** 그래서 「주소가 바뀌면 전원 재설치 — 며칠짜리 사고」는 **틀렸다.**
다시 깔아야 하는 사람은 원장·강사·학생 1명이다.

**새 앱(`v2`) — 2026-09-03 실측** (`zz_시험_` 픽스처 다섯이 섞여 있다):

| `v2.profiles` 역할 | 줄 | 로그인한 적 있음 |
|---|---|---|
| `principal` | 2 | 1 |
| `instructor` | 2 | 1 |
| `student` | 23 | **3** |
| `parent` | 21 | **0** |

`v2.students`에서 `zz_` 를 뺀 **진짜 학생은 23명**이다(원장님이 늘 말씀하시는 그 수와 맞다).

⚠️ **`v2.push_sub`는 0줄이다** — 새 앱에는 **알림 켠 기기가 아직 하나도 없다.**
위 「알림 켠 기기 3대」는 **옛 앱 쪽 수**다. 두 스키마를 섞어 세지 마라.

**그래서 진짜 일은 학부모 20명이 앱을 깔고 알림을 켜게 하는 것**이고, 그건 화면 품질이 아니라 **운영**이다 —
수업 오는 아이 폰에서 그 자리에서 깔아 주고, 학부모는 **아이 편에 안내지**를 보낸다.

### 켜는 것 / 되돌리는 것

**순서대로 켠다. 수업 시간 밖에.**

| 켜는 것 | 되돌리는 것 |
|---|---|
| PostgREST 노출 스키마에 **`v2`** 더하기 (잠깐 끊길 수 있다) | `v2` 빼기. ⚠️ **`public`을 빼지 마라** — 옛 앱이 그 자리에서 죽는다 |
| `auth.users` 트리거를 `v2.profiles`로 (**`public`용은 끄지 말고 남긴다**) | `drop trigger v2_on_auth_user on auth.users` |
| Storage 버킷·정책 (`9000` ③) | 정책 셋을 drop. 버킷은 파일이 들어 있으면 지우지 않는다 |
| **`NOTIFY_SINK=live`** (Production 환경변수) + 재배포 | `off` |
| **옛 앱에 역할 잠금 — 원장님만 로그인** | 잠금 풀기 |
| **Vercel 환경변수 `V2_PRODUCTION_OK=1`(Production) 켜기** — 없으면 `v2` 의 운영 빌드가 건너뛰어진다(`vercel.json` ignoreCommand · 대전제-13) | 변수 지우기 |
| **Vercel Production Branch를 `main` ▸ `v2`로** (마지막에) | 도로 `main`으로 한 칸 | **+ 재배포 한 번**(브랜치만 바꾸면 저절로 안 넘어온다) |

위 여섯이 `supabase/migrations/9000_switch_day.sql` 하나에 모여 있고 **되돌리는 줄이 짝으로 적혀 있다.**

### 켠 직후 확인

1. **원장님 폰에 설치된 앱 아이콘으로 열어** ① 새 화면이 뜨나 ② `zz_시험_` 계정에 시험 알림을 쏴서 **제대로 뜨고 눌렀을 때 맞는 화면이 열리나.** 옛 서비스워커가 아직 그 폰을 지배하고 있으면 여기서 드러난다.
2. **학생 한 명을 실제로 등록해** 계정 발급 → 로그인 → 자기 화면이 뜨는 것까지 끝을 본다. 트리거가 아직 `public`만 겨누고 있으면 그 아이는 로그인은 되는데 v2에 프로필 줄이 없어 **오류 없이 빈 화면**이 된다. 조용해서 며칠 뒤에야 발견된다.
3. **진도 체크를 첫 주에 켠다**(확정-㊶). 전환 시점에 진도가 비어 있으므로 **첫 주 숙제는 원장님이 손으로 내신다.** 전환 전주 미리보기에서 찍게 하면 마지막 재적재가 지운다.

### 옛 서비스워커 계약 — 첫 주만이라도 지킨다
