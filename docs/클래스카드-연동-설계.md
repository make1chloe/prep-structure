# 클래스카드 연동 설계 — 2026-08-16 (원장님과 확정)

전제 조사: 로컬 폴더 `클래스카드-조사-2026-08-12.md` (재조사 금지).
API 는 제공 안 함(원장님 확인). 방식은 **크롬 확장**(원장님, 2026-08-16
— 「맥미니 로봇 안 써봐서 크롬 연동하고 싶어」):

- 원장님이 늘 쓰는 크롬에 확장을 깐다 (개발자 모드 → 폴더 불러오기).
  **비번 저장이 아예 없다** — 이미 로그인된 크롬의 세션을 그대로 쓴다.
- 확장의 뒷단(background)이 시계(chrome.alarms)로 **수업 시간표에 맞춰**
  클카 내부 통신을 세션 쿠키로 호출해 플래너·진도율을 읽고, 앱의 수신
  주소로 보낸다. 크롬이 켜져 있는 동안은 완전 자동 — 수업 중에는 어차피
  앱을 크롬으로 쓰시니 조건이 저절로 맞는다.
- 확장 아이콘을 누르면 「마지막으로 보낸 시각」 과 「지금 읽기」 단추.
  비공식 접근이라 클카가 바뀌면 멈출 수 있다 — 조용히 멈춘 것이 제일
  무서우니 앱에도 마지막 수신 시각을 항상 표시한다.

## 확정된 갈래 (원장님, 2026-08-16)

| 숙제 | 방식 | 원장님 손 |
|---|---|---|
| 정규 단어 | **A** — 플래너가 원본. 앱은 「오늘 마감 세트 완료 여부」만 읽는다. 세트명은 매칭이 아니라 **표시용** | 0 |
| 독해·본문 | **B** — 교재 단원 ↔ 클카 세트를 **한 번만 잇는 지도** (단원에 세트 id 칸). 이름 유사도로 후보 추천, 확정은 원장님 탭 | 교재당 1번 |
| 문법 암기 등 수시 | **B'** — 내주는 순간 그 학생 세트 목록에서 골라 붙임 + 검사 기준(모드·목표%). 글로만 적으면 유사도 매칭 — **하나로 딱 떨어질 때만** 자동, 아니면 「골라주세요」 (학교 잇기와 같은 규칙) | 내줄 때 탭 1~2번 |

검사 판정: 지정 모드 진도율 ≥ 목표(기본 100%) = ○, 일부 = △(%표시),
0 = ✕. 수업 시작에 맞춰 반별로 읽어 오늘 수업 검사 줄에 미리 찍는다.

## 필수 감시 두 가지 (원장님, 2026-08-16 — 「이건 꼭 필요한 기능이야」)

1. **플래너 ↔ 앱 단어 진도 불일치 경고.**
   앱의 단어 진도(회독·단원 체크)와 플래너가 돌고 있는 Day 가 어긋나면
   — 예: 앱은 Day 8까지 나갔는데 플래너 마감은 아직 Day 4, 또는 반대 —
   대시보드와 오늘 수업 그 학생 줄에 「클카 플래너와 어긋남 (앱 Day 8 ·
   플래너 Day 4)」 로 띄운다. 판정은 단원 이름 정규화(Day/Lesson 숫자
   추출) 한 곳에서.
2. **플래너 소진 경고.**
   학생의 플래너 마감일이 앞으로 없거나 마지막 마감이 3일 안이면
   「플래너 새로 잡아야 함」 — 대시보드 경고 + 발송 「보낼 것」 화면이
   아니라 **할일**(수업 준비)로 자동 생성. 단어 교재가 끝나가는 것
   (대시보드 「곧 끝나는 교재」)과 나란히 보이게 한다.

## 내부 통신 지도 (2026-08-16 원장님 크롬에서 직접 확인 — A용은 완성)

플래너 리포트(`/Pro/ReportAllPlanner`) 기준. 로그인 세션 쿠키만 있으면
아래 둘로 A(플래너 판정)와 필수 감시 2종이 전부 된다.

1. **학생 목록** — 플래너 리포트 페이지의 학생 select (이름 + user_idx,
   24명). 응답의 `login_id` 가 앱 학생 아이디(chloe####)와 같아서
   **앱 학생 ↔ 클카 학생이 자동으로 이어진다** (수동 매핑 없음).
2. **마감일 달력** — `GET /Pro/ReportAllPlanner/0/{user_idx}/{년}/{월}`
   (달 넘기기가 부르는 주소). HTML 의 날짜 칸 class 로 판별:
   `td.day.planner` = 마감일 · `td.day.no-data` = 없음.
   → 감시② 플래너 소진: 앞으로 planner 날이 없거나 마지막이 3일 내.
3. **그날 학습 상태** — `POST /Pro/getPlannerLearnStatus`
   (form: `user_idx`, `date`) → `class_list[]`(class_idx · name ·
   class_category · login_id · user_name) → `set_list[]`:
   `set_idx · name · set_type · card_cnt · is_complete(불리언) ·
   learn_status(숫자) · learn_config(모드별 goal_yn/goal_score =
   필수학습 지정) · test_info · learn_summary`.
   → A 판정: is_complete / learn_status. 세트명(name)은 표시용 +
   Day 숫자 추출로 감시①(앱 단어 진도와 대조).

주의: 달 넘기기는 XHR 이 아니라 **페이지 전체 GET** — 확장에서는 fetch
로 받아 DOMParser 로 `td.day.planner` 만 읽으면 된다. B(세트 지도)용
클래스·세트 목록 주소는 B 만들 때 같은 방법으로 딴다.

## 만드는 순서

1. **내부 통신 지도 그리기** (원장님과 30분): 로그인된 크롬에서 플래너
   리포트·학생 학습현황을 열어 어떤 주소로 데이터가 오는지 확인한다.
2. **크롬 확장** (repo `extension/` — 개발자 모드로 불러오기):
   시간표 맞춰 읽기 + 앱으로 전송 + 팝업(마지막 전송·지금 읽기).
3. **앱 수신 + 저장** (0131 예정): classcard_sync(학생×세트×모드 진도,
   받은 시각) + 수신 주소(비밀키). 「마지막으로 받아온 시각」 표시.
4. **A 자동판정** — 오늘 수업 단어 숙제 줄에 플래너 완료 여부 자동 ○△✕.
5. **감시 두 가지** (위 필수) — 대시보드·오늘 수업·할일.
6. **B 지도** — 교재 단원 잇기 화면(추천+확정). **B'** — 배정 때 세트 선택.

## 앱이 하지 않는 것

- 플래너 설정 자체(마감일·세트 지정)는 클카에서 — 원본이 거기다 (원칙 1).
- 세트 내용 미러링·복제 금지 — 완료 여부와 진도율만 읽는다.
