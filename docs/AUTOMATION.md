# 자동화 현황과 이관 계획

노션에서 돌아가던 자동화를 조사해서, 웹앱으로 무엇을 어떻게 옮길지 정리한 문서.

---

## 1. 현재 자동화 구조

```
노션(데이터·버튼·체크박스)
   → Make(메이크, 시나리오 실행)
      → 바티 / 솔라피 (카카오 알림톡·문자 발송)
   → 과제 제출 폼(사진 업로드) → 노션 DB → 재원생 자동 연결
```

핵심 패턴은 **"체크박스로 대상 지정 → 버튼 클릭 → 발송 → 완료 체크"** 입니다.
발송 문구는 노션 수식(`[문구] 최종`, `[문구] 숙제현황`, `[문구] 테스트`)이
데이터를 조합해 자동 생성합니다.

---

## 2. 돌아가고 있는 자동화 목록

### 2-1. 발송 계열 (Make + 알림톡)

| 자동화 | 트리거 | 관련 속성 |
|---|---|---|
| **데일리리포트 발송** | 수업 후 버튼 | `[리포트]작성`, `[리포트]완료`, `[문구] 최종` |
| 재시험 안내 발송 | `발송예약` 체크 → 버튼 | `발송예약`, `발송완료` |
| 숙제 미제출 리마인드 | `숙제발송대상` 체크 → 버튼 | `숙제리마인드발송완료`, `숙제경과일` |
| 입학/첫수업 문자 | 체크박스 | `입학문자`, `첫수업문자`, `첫수업문자발송` |
| 결석·보강 안내 | 버튼 | `결석보강안내`, 보강문자DB |
| 지각 안내 | 버튼 | `지각안내완료` |
| 월말 리포트 | 버튼 | `월말레포트생성`, 월말레포트DB |

### 2-2. 기록 계열 (노션 버튼)

출석 / 지각 / 결석 / 보강 / 신규등원 / 첫등록 / 퇴원 / 출석리셋 /
성적 입력 / 모고인쇄 / 수업준비 / 상담

→ 버튼 하나로 해당 DB에 행을 만들거나 상태를 바꾸는 방식.

### 2-3. 연결 계열 (Make)

- 과제 제출 폼으로 들어온 사진을 **학생 이름으로 재원생DB에 자동 연결**
  (이름이 틀리면 수동 연결 필요 → 매일 확인하는 업무가 따로 있음)

---

## 3. 웹앱 이관 판단

### 3-1. 앱 기능으로 대체 (별도 자동화 불필요)

| 노션 자동화 | 앱에서는 |
|---|---|
| 출석/지각/결석 버튼 | 출석부 화면에서 클릭 한 번 |
| 성적·수업준비·모고인쇄 버튼 | 각 화면의 실제 버튼 |
| 출석리셋 | 날짜별로 데이터가 분리되므로 리셋 개념 자체가 사라짐 |
| `[문구]` 수식들 | 저장한 데이터로 앱이 문구를 생성 |
| 재원생 자동 연결 | 학생을 선택해서 입력하므로 연결 오류가 발생하지 않음 |
| 발송예약/발송완료 체크 | 발송 이력 테이블(`sent_at`, `kakao_status`)로 자동 기록 |

→ **노션 자동화의 상당수는 "노션이라서 필요했던 우회"** 입니다.
앱에서는 화면 동작 자체가 그 일을 하므로 옮길 필요가 없습니다.

### 3-2. 반드시 옮겨야 하는 것 (실제 외부 발송)

| 항목 | 방식 |
|---|---|
| 데일리리포트 알림톡 | 앱에서 문구 생성 → 발송 API 호출 |
| 재시험/미제출 리마인드 | 대상 자동 추출 → 일괄 발송 |
| 결석·보강 안내 | 출결 기록에서 자동 대상 추출 |
| 입학/첫수업 안내 | 신규생 등록 시 |
| 월말 리포트 | 월 단위 집계 → 발송 |

발송 수단은 현재 **바티 / 솔라피**를 쓰고 있으므로, 앱에서도 같은 서비스의
API를 호출하면 기존 템플릿을 그대로 쓸 수 있습니다.

### 3-3. 옮길지 결정이 필요한 것

- **과제 사진 제출 폼** — 학생이 사진을 올리는 통로.
  앱에 학생 로그인이 생기면 앱 안에서 제출받는 게 자연스럽지만,
  학생 입장에서는 링크 하나로 올리는 지금 방식이 더 편할 수 있음.

---

## 4. 이관 순서 (로드맵과 연결)

| 시점 | 할 일 |
|---|---|
| 3단계(데일리리포트) 때 | 리포트 문구 자동 생성 — 발송 없이 **미리보기·복사**까지 |
| 3단계 이후 | 발송 API 연동 (바티/솔라피 키 필요) |
| 5단계(출결) 때 | 결석·보강·지각 안내 대상 자동 추출 |
| 7단계 | 월말 리포트 집계·발송 |

> 발송 연동은 **문구 생성이 정확해진 뒤**에 붙이는 게 안전합니다.
> 잘못된 문구가 학부모에게 나가면 되돌릴 수 없기 때문에,
> 먼저 화면에서 문구를 확인하고 복사해 쓰는 단계를 거칩니다.

---

## 5. 발송 연동 시 필요한 정보 (나중에 준비)

- 바티 또는 솔라피 **API 키**
- 등록된 **알림톡 템플릿 코드** (데일리리포트, 재시험, 결석 등)
- 발신 프로필 / 발신번호

이 값들은 코드에 넣지 않고 **환경변수**로만 보관합니다.
