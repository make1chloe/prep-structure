# 클로이영어 학습관리 — 이관 로드맵

노션(1~7월 실사용) DB를 전수 확인하고, 웹앱으로 옮길 수 있는지 대조한 결과와
단계별 구축 순서를 정리한 문서.

---

## 1. 노션 DB 전수 조사 결과

### 1-1. 핵심 DB (매일 사용, 없으면 구조가 안 돌아감)

| 노션 DB | 역할 | 앱 이관 | 상태 |
|---|---|---|---|
| 3재원생DB | 학생 마스터 + 당일 숙제/학습 임시칸 | `students` | ✅ 완료 |
| 3교재DB | 교재 마스터 | `textbooks` | ✅ 완료 |
| 커리큘럼DB | 교재별 단원(제목·순서·활동) | `textbook_units` | ✅ 완료 |
| 3수업DB | 반(요일·시간·강의실·정원·담임) | `classes` | ⚠️ 일부 부족 |
| 3데일리리포트DB | 당일 출결·테스트·숙제·태도·리포트 | `daily_reports` | ⚠️ 대폭 부족 |
| 3수업일정DB | 날짜별 수업 회차 | 없음 | ❌ 신규 필요 |
| 공통진도DB | 반 공통 진도 | 없음 | ❌ 신규 필요 |
| 수납및출결DB | 교육비·출결 집계 | 없음 | ❌ 신규 필요 |

### 1-2. 보조 DB (주기적 사용)

| 노션 DB | 역할 | 우선순위 |
|---|---|---|
| 3학교DB | 학교별 내신교과서·시험일정 | 중 (내신 트랙) |
| 학생별성적DB | 내신/모의고사 성적 | 중 |
| 재원생상담일지DB | 상담 이력 | 중 |
| 방문상담목록DB | 신규생 유입·상담 | 중 |
| 월말레포트DB | 월말 리포트 | 하 |
| 하원숙제DB | 하원 시 숙제 배정 | 하 (데일리리포트로 흡수 가능) |
| 보강문자DB | 보강 안내 발송 | 하 |
| 시험범위DB | 내신 시험범위 | 중 (내신 트랙) |

### 1-3. 이관하지 않는 것 (노션 전용 기능)

- **수식(formula) 컬럼** — 앱에서는 화면에서 계산하므로 저장 불필요
  (예: 재원기간, 다음수업일, 출석횟수, 정답률, 문구 자동생성)
- **롤업(rollup)** — 관계로 조회하면 되므로 불필요
- **버튼(button)** — 앱에서는 실제 버튼/액션으로 대체
- **우피URL, 메이크 연동용 텍스트** — 외부 도구 전용

> 결론: 노션의 약 120개 속성 중 **실제로 저장이 필요한 값은 60여 개**.
> 나머지는 계산·연동용이라 앱에서는 자동 처리된다.

## 2. 스키마 격차 (보강 필요)

### 2-1. classes (반)
| 필요 | 현재 | 조치 |
|---|---|---|
| 초중고 구분 | 없음 | `school_level` 추가 |
| 강의실 | `room` 있음 | 그대로 |
| 반–교재 연결 | 없음 | `class_textbooks` 신설 |

### 2-2. daily_reports (데일리리포트) — 가장 큰 격차
노션에서 매일 기록하는 항목:
- 출결: 정시출석 / 지각 / 조퇴 / 결석 / 보강 / 숙제검사 / 온라인 / 지각(학교일정)
- 태도: 5단계 (Excellent ~ Area of Concern)
- 테스트: 통과 / 미통과 / 미등원, 결과 10종
- 단어·문장 테스트 점수: 맞은 개수 / 전체 개수, 재시 점수
- 숙제 상태: 완료O / 미흡△ / 미제출X (각각 40여 개 항목 다중선택)
- 인증숙제, 개별진도, 특강진도, 공지
- 리포트 작성/완료 체크

→ 항목 목록이 계속 바뀌므로 **고정 컬럼이 아니라 마스터 테이블 + 다중선택**으로 설계.
`homework_items`(숙제 항목 마스터) + `daily_report_items`(리포트별 항목·상태)

### 2-3. 신규 테이블
- `class_sessions` — 날짜별 수업 회차 (수업일정DB)
- `class_progress` — 반 공통 진도 (공통진도DB)
- `payments` — 교육비 수납 (수납및출결DB)
- `schools` — 학교·내신교과서 (3학교DB)
- `consultations` — 상담일지
- `scores` — 성적

## 3. 단계별 구축 순서

### ✅ 1단계 — 기반 (완료)
로그인 · 배포 · 학생 관리(전 속성, 엑셀 업로드, 선택/수정/삭제) ·
교재 관리(단원 대중소 계층, 활동, 엑셀 업로드)

### 2단계 — 반 · 시간표 (다음)
1. `classes` 보강 + 반 관리 화면 (요일·시간·강의실·정원·담임·초중고)
2. 반에 학생 배정 (드래그 없이 체크박스 다중 배정)
3. 반–교재 연결
4. 오늘 수업 목록 (요일 기준 자동)

### 3단계 — 데일리리포트 (핵심)
1. 숙제 항목 마스터 관리 화면 (완료/미흡/미제출에 쓰는 항목들)
2. 반별 출석부 화면 — 학생 줄 × 항목 열, 한 화면에서 체크
3. 테스트 점수 입력 (단어/문장, 맞은개수/전체, 재시)
4. 태도·공지·개별진도
5. 리포트 문구 자동 생성 (노션 수식 대체)

### 4단계 — 진도 관리
1. 학생별 통합진도 (학습방식 + 교재/단원)
2. 반 공통 진도
3. 교재별 진도 현황 한눈에 보기

### 5단계 — 출결 · 수납
1. 월별 출결 집계
2. 교육비 수납 관리
3. 보강 관리

### 6단계 — 내신 트랙
학교DB · 시험범위 · 내신 교재 · 성적 관리

### 7단계 — 상담 · 신규생
방문상담 · 재원생 상담일지 · 월말 리포트

## 4. 설계 원칙 (지금까지 확정된 것)

1. **화면 만들기 전에 DB 속성을 먼저 나열하고 불필요한 것을 제거**한다.
2. 입력은 **엑셀 양식 다운로드 → 파일 업로드**를 기본으로 한다.
   (직접 추가 폼은 접이식 보조 수단)
3. 모든 목록은 **전체/일부 선택 → 수정 · 삭제 · 변경 · 이동**이 가능해야 한다.
4. 학생 로그인 아이디는 `chloe + 전화 뒷자리 4`, 충돌 시 `-2`, `-3`.
   기본 비밀번호 `0000`, 첫 로그인 후 학생이 변경.
5. 노션의 수식·롤업·버튼은 저장하지 않고 앱 기능으로 대체한다.
6. 항목이 자주 바뀌는 값(숙제 종류 등)은 컬럼이 아니라 **마스터 테이블**로 둔다.
