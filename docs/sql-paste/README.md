# 실 DB 에 붙여넣을 SQL — 원장님용

Supabase → **SQL Editor** → **New query** → 파일을 통째로 붙여넣고 **Run**.

## ⚠️ 먼저 이것부터 (2026-09-11)

`0156-0159.sql` 이 **「56개 중 48개」** 라며 멈췄습니다 — 실 DB 에 **0100~0155 중 8개가 안 들어가** 있습니다.
(제가 「0155 까지 다 들어갔다」고 적어 두었던 것이 **틀렸습니다**.)
문지기가 막은 것이 맞게 돈 것입니다 — **아무것도 안 들어갔으니 DB 는 그대로입니다.**

| 차례 | 파일 | 무엇 |
|---|---|---|
| **①** | `0-어디까지-들어갔나.sql` | **읽기만 합니다.** 비어 있는 번호를 **한 줄**로 보여 줍니다(예: `0106 0114 0128 …`) → 그 줄을 주시면 ②를 만들어 드립니다 |
| ② | (①의 답을 보고 만듭니다) | 빠진 8개 + 0156~0159 를 **번호 차례대로** 이어 붙인 한 파일 |
| ~~③~~ | ~~`0156-0159.sql`~~ | ②에 함께 담깁니다 — **이것만 따로 돌리면 안 됩니다**(앞 것이 없으면 문지기가 막습니다) |

⚠️ **SQL Editor 는 맨 마지막 `select` 하나만 보여 줍니다.** 그래서 ①은 **한 문장**으로 만들었습니다(2026-09-11 — 처음에 두 문장으로 드려 셈만 보이고 이름이 안 나왔습니다).

## 늘 같은 것

- **통째로 한 트랜잭션입니다** — 하나라도 틀리면 아무것도 안 들어갑니다. 실패하면 고쳐서 **그대로 다시** 붙여넣으면 됩니다.
- 맨 끝에 `notify pgrst, 'reload schema';` 가 이미 들어 있습니다(표에 칸을 더해도 화면이 그 칸을 못 쓰던 일 — 원장님 9/10 밤).
- **다 들어간 뒤에 또 돌리면 안 됩니다** — 0106·0114·0128 에서 멈춥니다(뒤 파일이 같은 함수를 다른 반환형으로 다시 냅니다). 그래서 문지기가 먼저 셉니다.

이 파일들은 `supabase/migrations/` 의 원본을 번호 차례대로 이어 붙인 것이고,
`node scripts/build-real-db-sql.mjs <파일이름들>` 로 다시 만듭니다.
