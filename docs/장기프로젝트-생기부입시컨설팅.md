# 생기부 · 입시 컨설팅 도구

캡쳐 세 장(대시보드 · 수행평가 아카이브 · 자료 정리 화면)을 뜯어보고,
어떻게 만들 수 있는지 정리한 문서. **클로이영어 앱과는 다른 프로젝트**다
(영어학원 학습관리 ↔ 생기부·입시 컨설팅). 다만 **이미 만들어둔 조각을
상당 부분 그대로 쓸 수 있다** — 그 대응을 뒤에 적어둔다.

---

## 1. 화면에서 읽은 것

### 1-1. 대시보드 — 「학생 관리 보드를 중심으로」

한 줄로 늘어선 아홉 개의 입구. 성격이 셋으로 갈린다.

| 묶음 | 입구 | 하는 일 |
|---|---|---|
| **만들기** | 새 분석 · 수행평가 도우미 · 입시 상담 | AI 가 글을 쓴다 |
| **찾아보기** | 대학 입결 조회 · 대학별 입시정보 · 입결 콘솔 | 쌓아둔 자료를 뒤진다 |
| **쌓기** | 수행평가 아카이브 · 학생 목록 · 분석 불러오기 | 만든 것을 보관하고 다시 쓴다 |

그 아래가 **학생 관리 보드** — 칸반이다.

```
신규 5 → 생기부 분석 3 → 보완 중 1 → 수행평가 0 → 완료 0
```

옆에 `선생님: 관리자(나)` 고르는 칸과 `관리자 보기` 버튼.
**여러 선생님이 나눠 맡고, 관리자는 전부 본다**는 뜻이다.

> ⚠️ **「분석 불러오기 — JSON 파일 열기」가 걸린다.**
> 이건 서버에 안 담고 파일로 주고받던 흔적이다. 학생이 늘면
> "그 분석 어디 갔지" 가 반드시 온다. 처음부터 계정 + DB 로 가야 한다.

### 1-2. 수행평가 아카이브 — **이 도구의 핵심**

화면 설명 그대로:

> 기존에 만들어둔 수행평가 자료(PDF·워드·텍스트)를 올리면 AI가 상세 정리하고,
> 학교·분야·주제별로 보관합니다. 보관된 자료는 언제든 다시 열어 **다른 학생에게
> [미리 준비]로 배정**할 수 있습니다.

**「다시 열어 다른 학생에게 배정」 — 여기가 전부다.**
한 번 정리해두면 다음 학생에게는 정리하는 일이 없다.
클로이영어의 교재 단원 DB 와 **같은 성질**이다 — 쌓을수록 일이 줄어든다.

보관된 자료 한 줄의 모습:

```
2학년 논리와 사고 수행평가 자료(활동지 및 자기평가서 양식) 정리
[경남외국어고등학교] [국어(논리와 사고)] [고2] [보고서/발표/포트폴리오(자기평가서)]
독서 논증 탐구, 시사 담론 논리적 오류 분석 및 학업 역량 자기평가      2026-08-01
```

찾는 방법이 넷: **검색(제목·주제·내용) / 학교 / 분야 / 배정할 학생**.

### 1-3. 자료 정리 화면 — AI 가 쓰고 사람이 고친다

흐름이 셋으로 끊겨 있다.

1. **올린다** — 여러 파일을 한꺼번에. PDF·docx·hwp/hwpx·txt
2. **AI 로 상세 정리** — 뽑아낸 글을 보여주고, 누르면 정리한다
3. **정리 결과 확인 · 분류 후 저장** — 칸이 전부 **고칠 수 있게** 열려 있다
   `제목 / 학교 / 분야·과목 / 주제 / 학년 / 유형`
   본문에는 **과제 요구사항 표**(과제명 · 분량 및 형식 · 주요 평가/요구 기준)
   그리고 `💾 아카이브에 저장` / `버리기`

> ✅ **이 화면이 제일 잘 만들어졌다.**
> AI 가 정한 것을 그대로 저장하지 않는다. **사람이 보고 고친 뒤에** 들어간다.
> 우리가 나이스 학사일정에서 내린 결론과 같다 — *기계가 제안하고, 사람이 정한다.*

## 2. 어떻게 만들 것인가

### 2-1. 자료 한 장이 지나가는 길

```
파일 올리기
  └ 글 뽑기 (PDF / docx / hwp / hwpx / 이미지)
      └ 스캔본이면 OCR
          └ AI 정리 (구조를 정해서 받는다)
              └ 사람이 고친다  ← 여기서 멈춘다. 자동 저장 안 한다
                  └ 아카이브에 저장
                      └ 다른 학생에게 배정
```

### 2-2. 글 뽑기 — **한글(hwp)이 제일 어렵다**

| 형식 | 방법 | 난이도 |
|---|---|---|
| txt | 그대로 | 쉬움 |
| docx | zip + XML (`word/document.xml`) | 쉬움 |
| **hwpx** | zip + XML — **hwp 의 신형이라 다루기 쉽다** | 쉬움 |
| pdf (글자) | `pdf.js` / `pdfminer` | 보통 |
| pdf (스캔) | OCR — 한글 인식률이 관건 | 어려움 |
| **hwp (구형)** | 바이너리 복합문서. `pyhwp` 등 | **어려움** |

**정할 것**: 구형 hwp 를 붙들고 있을지.
현실적인 답은 **「hwpx 로 저장해서 올려주세요」 라고 안내하고, 구형 hwp 는
못 읽으면 못 읽는다고 말해주는 것**이다. 조용히 빈 글을 넘기면 AI 가
엉뚱한 것을 정리해서 저장해버린다 — 그게 제일 나쁘다.

OCR 은 클라우드(구글/네이버) 를 쓰는 편이 낫다. 자체 OCR 은 한글 손글씨·표에서
무너진다. **다만 학생 자료를 밖으로 보내는 것이므로 뒤(§4)의 개인정보를 먼저 볼 것.**

### 2-3. AI 정리는 **모양을 정해서 받는다**

자유롭게 쓰게 두면 매번 다른 모양이 와서 분류가 안 된다.
받을 모양을 미리 정하고 그대로 달라고 한다 (JSON schema / tool use).

```json
{
  "title":   "2학년 논리와 사고 수행평가 자료 정리",
  "school":  "경남외국어고등학교",
  "subject": "국어(논리와 사고)",
  "grade":   "고2",
  "type":    "보고서/발표/포트폴리오(자기평가서)",
  "topics":  ["독서 논증 탐구", "시사 담론 논리적 오류 분석"],
  "tasks": [
    { "name": "독서 기반 논증 탐구 보고서",
      "format": "A4 1~2쪽 이상",
      "criteria": "표절 금지, 기한 내 제출 (미제출 시 미이수)" }
  ],
  "body_md": "…내용 상세 정리 (표는 마크다운으로)…"
}
```

- `type` · `subject` 는 **골라 쓰는 목록**으로 두고, 없으면 새로 만든다.
  자유 입력으로 두면 「보고서」 「보고서/발표」 「발표보고서」 가 다 생긴다.
  → **클로이영어의 `school_key()` · `bookKey()` 와 같은 열쇠 방식**을 그대로 쓴다.
- `school` 도 마찬가지. **`schools` 표를 그대로 가져다 쓴다** (§5).

### 2-4. 표

```
학생 (students)
  이름 · 학년 · 학교 → schools
  담당 선생님 → profiles
  상태  신규 | 생기부분석 | 보완중 | 수행평가 | 완료   ← 칸반이 이걸 읽는다

자료 (assets)            ← 아카이브 한 줄
  제목 · 학교 → schools · 과목 · 학년 · 유형
  주제 text[] · 요구사항 jsonb · 본문 md
  원본 파일들 → storage
  만든 사람 · 만든 날

배정 (asset_assignments)  ← 「다른 학생에게 미리 준비로 배정」
  자료 → 학생 · 배정한 날 · 상태(준비중|전달함|끝) · 메모

분석 (analyses)          ← 「새 분석」 이 만든 것
  학생 → · 종류(생기부종합|수행평가|상담) · 입력 · 결과 md · 만든 날
  ※ 「분석 불러오기(JSON)」 는 이 표로 대체된다

대학 (universities) / 입결 (admissions)
  대학 · 학과 · 연도 · 전형(정시|수시|논술) · 등급컷 · 경쟁률 · 충원
```

**칸반은 상태 하나로 돌아간다.** 별도 표를 만들지 않는다 —
클로이영어 재원생의 `status`(재원·휴원·퇴원) 와 같은 방식.

### 2-5. 입결 — **여기는 만들기가 아니라 모으기다**

「대학 입결 조회」 · 「대학별 입시정보」 · 「입결 콘솔(다개년 추이·배치 판정)」
셋 다 **자료가 있어야 시작되는 화면**이다. 코드는 절반도 안 된다.

- 출처를 정하고 (대학알리미 · 어디가 · 각 대학 공시), **언제 것인지 화면에 적는다.**
  입결은 해마다 바뀌고, 오래된 숫자로 상담하면 사고다.
- 다개년 추이는 **연도별 한 줄씩** 쌓는 구조라야 한다 (덮어쓰면 추이가 사라진다).
  → 나이스 학사일정에서 배운 것과 같다. **받아온 것과 내가 적은 것을 섞지 않는다.**
- 「배치 판정」은 판단이므로 **근거를 같이 보여준다.**
  "안정" 이라고만 뜨면 왜 그런지 물어볼 데가 없다.

> 이 갈래는 **뒤로 미뤄도 된다.** 아카이브·분석 없이 입결만 있으면 쓸모가 적지만,
> 반대는 성립한다.

## 3. 만드는 순서

각 단계가 **혼자서도 쓸모 있게** 끊는다.

1. **자료 한 장을 올려 정리하고 저장하기**
   파일 → 글 뽑기 → AI 정리 → 고치기 → 저장.
   이것만 돌아가도 "정리해두는 도구" 로 쓸 수 있다.
2. **아카이브 찾기 · 배정**
   검색 · 학교 · 분야로 좁히고, 학생에게 배정.
   → **여기서부터 쌓을수록 일이 줄어든다.** 제일 먼저 체감된다.
3. **학생 + 칸반**
   상태로 흐름을 만들고 담당 선생님을 나눈다.
4. **분석 (생기부 종합 · 수행평가 도우미)**
   결과를 DB 에 담는다. JSON 파일 주고받기를 없앤다.
5. **입시 상담 (AI)**
   1~4 가 쌓여야 대답할 거리가 생긴다.
6. **입결**
   자료 모으기가 절반. 마지막에.

## 4. 먼저 정해야 할 것 ⚠️

### 개인정보

**생기부와 수행평가는 학생 개인정보다.** 클로이영어의 출결·성적보다 무겁다.

- 자료를 **AI 에 보낸다**는 것은 밖으로 나간다는 뜻이다. 어디로 가는지,
  학습에 쓰이는지, 지우면 지워지는지를 **부모님께 설명할 수 있어야** 한다.
- 이름·학번을 자료에서 **지우고 보낼 수 있는지** 본다 (가려서 보내기).
- 보관 기간을 정한다. 졸업하면 언제 지우는가.

### 저작권 · 표절

- 활동지·평가 기준은 **학교가 만든 것**이다. 보관은 몰라도 배포는 다른 문제다.
- 「다른 학생에게 재활용」이 **베끼기로 읽히지 않게** 해야 한다.
  자료는 *과제가 무엇을 요구하는지* 를 정리한 것이지 *답* 이 아니다.
  화면의 말과 저장하는 모양이 그 선을 지켜야 한다.

### 여러 선생님

`관리자 보기` 가 있다는 것은 **선생님마다 보는 것이 다르다**는 뜻이다.
클로이영어에서 배운 대로 — **막는 곳이 하나면 그 하나가 뚫렸을 때 끝난다.**
DB 권한(RLS)으로 막고, 화면으로 또 막는다.

## 5. 클로이영어에서 그대로 가져올 것

새로 만들 필요가 없는 것들. **이미 만들어서 검사까지 붙어 있다.**

| 필요한 것 | 이미 있는 것 |
|---|---|
| 학교 표 · 이름 정규화 | `schools` + `school_key()` + `lib/schoolName.js` (0076) |
| 과목·유형 이름이 갈리는 것 막기 | `lib/bookName.js` 의 **열쇠** 방식 |
| AI 가 쓰고 사람이 고치기 | `app/ai/actions.js` 의 `draftNotices` |
| 받아온 것 ↔ 내가 적은 것 안 섞기 | 시험–나이스 붙이기 (0075) 의 **주인/참고** 구조 |
| 파일 보관 + 권한 | `homework_submissions` + 저장소 정책 (0044·0047) |
| 목록 골라서 한 번에 처리 | `components/Bulk.jsx` |
| 상태로 흐름 만들기 | `students.status` |
| 마이그레이션이 진짜 옮기는지 검사 | `scripts/check-exam-merge.sh` 의 방식 |
| 학생·학부모에게 안 새게 하기 | `scripts/check-leak.sh` (진짜 Postgres 로 확인) |

> 특히 **§2-3 의 「모양을 정해서 받는다」와 §1-3 의 「사람이 고친 뒤 저장」**은
> 클로이영어에서 이미 두 번 값을 치르고 배운 것이다.
> 처음부터 그렇게 시작하면 된다.

## 6. 아직 모르는 것

- 이 도구를 **누가 쓰나** — 원장님 혼자? 컨설팅 선생님 여럿? 학생도 보나?
  칸반에 「선생님」 칸이 있는 걸 보면 여럿 같은데, 그러면 권한 설계가 먼저다.
- 캡쳐의 도구가 **직접 만드시는 것인지, 보고 참고하시는 것인지**
- 클로이영어와 **합칠 것인지 따로 둘 것인지**
  → 학생이 겹치면 합치는 편이 낫고(학교 표를 같이 쓴다), 겹치지 않으면 따로가 낫다
- 구형 hwp 를 지원할 것인지 (§2-2)
- 입결 자료를 어디서 가져올 것인지 (§2-5)
