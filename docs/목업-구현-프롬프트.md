> 아래 프롬프트는 세션이 읽는다. CLAUDE.md · `docs/규칙.md` 는 세션이 스스로 읽으므로 여기에 두 벌로 적지 않는다.

## 프롬프트

목업을 그대로, 되면 더 낫게 — 새 앱을 처음부터 짓는다.

**■ 무엇** — `docs/목업/클로이영어-화면-목업.html` 의 27화면(s0~s20)이 명세다. 기록 페이지(notes)의 「정한 것」·「여쭐 것」·「안 되는 것」도 명세의 일부다. 겉은 `docs/디자인-기본.md`(배색 다섯 벌 · 치수 · 글꼴 · 금지 9)다.

**■ 버린다** — `app/` `lib/` `components/` `middleware.*` 와 옛 화면·판단에 묶인 `scripts/check-*` 전부. 지우고 시작한다. 옛 코드를 베끼지 않는다(대전제-11). git 역사에 남아 있으니 참고만 한다.

**■ 남긴다** — `docs/` 전부 · 배포 설정 · DB 를 지키는 검사(`check-v2only` `check-migrations` `check-schema` `check-grants` `check-sql`) · **스키마 `v2` 와 그 안의 데이터 그대로** — 사람(학생 23 · 학부모 21 · 원장·강사·조교) · 권한 32칸 · 교재 · 진도 · 시험 · 큐가 다 거기 있고 목업에서 유도된 표다. 새로 필요한 표만 v2 에 더한다(9/5 밤 정정: 스키마를 하나 더 두면 같은 표가 두 벌이 된다 — 원칙-1). `auth.` `storage.` `public.` 은 건드리지 않는다. 비밀번호는 건드리지 않는다. `main` 은 절대 푸시하지 않는다.

**■ 잣대** — 「더 낫게」는 잣대 넷을 통과할 때만이다: 원장 일이 줄어드나 · 한눈에 보이나 · 빠른가(속도 대원칙 4) · 클릭이 안 늘었나. 통과한 것은 `docs/목업보다-나아진-것.md` 에 화면 · 전 · 후 · 까닭으로 적는다. 원장님이 한 줄로 되돌릴 수 있어야 한다. 근거 없는 「더 예쁘다」는 안 된다.

### 순서 — 앞 것이 끝나야 뒤 것을 시작한다

0. **겉 한 벌.** 목업 `<style>` 의 토큰(배색 다섯 벌 · 치수 · 글꼴 · 글씨 열 단계)을 `app/globals.css` 로 옮긴다. `docs/목업/` 의 검사 넷(contrast · contrast2 · audit · fonts)을 `scripts/check-palette` `check-sizes` `check-fonts` 로 옮겨 **앱 화면**에 돌린다. 앱 토큰 = 목업 토큰인지 `check-mockup` 이 대조한다. e2e 틀(로컬 Postgres · PostgREST · 인증 흉내, 옛 앱 `scripts/e2e` 참고)을 세운다.
1. **뼈대.** 로그인 s0 · 세션(`lib/session.js` sessionUser, `auth.getUser()` 금지) · 권한(원장·강사·조교·학생·학부모 — 기본값은 코드에 안 박고 원장님이 웹에서 정한다) · 메뉴(어디서든 나가는 길) · 배색 고르기 · 큐·자동화 뼈대(규칙.md 뼈대-1~11).
2. **하루 동선.** 오늘 수업 s1(+조절 s2 · 진도 체크 s2b · 결석 예정 s2c · 폰 s3) → 대시보드 s17 → 학생 s7 · 달력 s9b → 학부모 s9 → 발송 s10 → 루틴 s11.
3. **달·학기.** 일정 s12 · 학사일정 받아오기 s12b → 수강료 s13 → 시험 회차 s6b → 성적 s16 → 교재 s15 · 엑셀 s15b → 보드 A s4 · 로드맵 s8 · 내 할 일 s6 · 표 s6c → 학생 s14 · 신규 상담 s18 → 자료함 s20 · 영상 s19.

### 화면 하나를 지을 때마다 — 같은 여덟 걸음

1. 목업의 그 화면을 열어 **부품 · 판단 · 상태**(빈 것 · 0개 · 중복 · 같은 아이 여럿 · 폰)를 **목록으로** 적어 보여준다. 목록이 곧 계획이다(듣기-3).
2. 표가 필요하면 **마이그레이션 먼저**, 멱등하게(`check-sql` 이 3번 돌린다).
3. 판단은 `lib/` **한 벌**(규칙.md 「판단이 사는 곳」), 화면은 가져다 쓴다. 같은 값을 두 벌로 그리지 않는다(원칙-1).
4. 화면은 **목업 HTML 구조를 그대로** React 로. 조회는 파도(`Promise.all`) 하나, 칩·토글은 낙관적, 배지는 메모.
5. **검사를 하나 이상 더한다** — 이 화면의 규칙 중 「지킴: —」 인 것부터. 화면이 끝났는데 검사가 안 늘었으면 안 끝난 것이다(원칙-6).
6. `SKIP_BUILD=1 bash scripts/check-all.sh` + `npx next build --webpack` + e2e 캡처 **PC 1280 · 폰 390(손가락)**. 목업 캡처와 나란히 놓고 다른 곳을 목록으로. 검사 결과는 사람이 거르지 않는다 — 실패는 종료 코드가 말한다.
7. 커밋 → 작업 브랜치와 `v2` **둘 다** 푸시. `docs/지금까지.md` 를 갱신한다 — 세션은 잊고 문서만 기억한다.
8. 보고 여섯 줄: 화면 · 검사 결과(**실패만**) · 목업과 다른 곳 · 나아진 것 · **여쭐 것 하나**(없으면 「없음」) · 다음 화면.

### 답이 없는 자리는 이렇게

- ⑬ 알림 열쇠 · 06c 표 ①~④ 는 `docs/원장님-정하실-것.md` 의 제안값으로 짓고, 화면에 「원장님 답 기다림」 표시를 남긴다. 답이 오면 그 줄만 바꾼다. 이미 답하신 것은 다시 여쭙지 않는다(듣기-4).
- 클래스카드 받아 적기는 브라우저 확장을 따로 짓는다 — 앱은 **받는 쪽**을 먼저.
- 「어떻게」만 비면 정해서 「경계」 줄에 적고 간다. 「무엇」이 안 잡히면 한 줄로 묻는다.

### 끝의 정의

- 27화면 전부 · `check-all` 초록 · `docs/규칙.md` 의 「지킴: —」 **0** · 대비·치수·글꼴·겹침 검사가 **앱**에서 통과 · 폰 넘침·겹침 0 · 원장님 하루 동선의 클릭 수 ≤ 목업.
- 끝나면 `docs/개발자-인수인계.md` 를 새로 쓴다 — 무엇을 어디에 지었고, 검사가 무엇을 지키는지.

### 늘

- 원장님 말씀은 듣기-1~5 로 — 되짚고 시작, 여쭙는 것은 하나, 답은 그날 문서에.
- 설명은 짧게, 결론 먼저. 모르면 「모릅니다」. 숫자는 센 것만, 어디서 셌는지 밝힌다.
- 이 프롬프트는 여러 세션에 걸쳐 쓴다. 시작할 때 `docs/지금까지.md` 를 읽고, 끝날 때 갱신한다.
