# 옛 서비스워커 계약서 — 새 앱 `notify` 가 지켜야 할 것

> **왜 이 문서인가**: 주소(origin)를 그대로 물려받으므로 **폰에 박힌 옛 알림 프로그램(SW)이 살아 있다.**
> 전환일 저녁 첫 알림은 **모든 폰에서 옛 SW가 받는다.** 확률이 아니라 확정이다 —
> 새 SW는 그 폰이 새 앱을 **한 번 열어야** 설치되는데, 학부모는 보통 **알림이 와야** 앱을 연다.
> 보내는 글의 모양이 다르면 **알림이 아예 안 뜨거나 눌렀을 때 404** 가 된다.
> 원장님 PC에서는 새 앱이 멀쩡하므로 **며칠간 모른다.**
>
> 읽은 것: `public/sw.js` · `lib/push.js` · `app/push/actions.js` · `lib/notify.js` (2026-09-02)

---

## ① 파일 경로와 스코프

```
public/sw.js          navigator.serviceWorker.register("/sw.js")   ← 루트 스코프
```

- `install` → **`self.skipWaiting()`**
- `activate` → **`e.waitUntil(clients.claim())`**

✅ **계획이 요구한 「기다리지 않고 바로 넘겨받게」가 이미 되어 있다.**
새 SW도 **같은 경로 `/sw.js` · 루트 스코프 · 같은 두 줄**로 낸다.
**스코프가 좁아지면 안 되고, 옛 등록을 지우면 안 된다** — 지우는 순간 그 폰의 구독이 죽는다.

## ② push 핸들러가 읽는 글 모양

```json
{ "title": "...", "body": "...", "tag": "...", "url": "...", "r": 123 }
```

| 칸 | 없으면 | 쓰이는 곳 |
|---|---|---|
| `title` | `"클로이영어"` | 알림 제목 |
| `body` | `""` | 알림 본문 |
| `tag` | `"chloe"` | ⚠️ **같은 tag 는 덮어쓴다.** 갈래마다 달라야 한다 |
| `url` | `"/me"` | 눌렀을 때 여는 주소 |
| `r` | `null` | 알림 자취 번호 |

아이콘은 **`/api/icon/192`** (icon·badge 둘 다). **새 앱에 이 주소가 있어야 한다.**

⚠️ **`tag` 는 지금 앱이 갈래마다 다르게 싣고 있다** — `send-daily` · `send-late` · `send-notice` ·
`makeup-change` · `break` · `unittest` · `monthly-2026-09` · `notice-{kind}` · `test`.
**형제가 있는 집도 안전하다** — 학부모 구독을 `[...new Set(...)]` 로 한 번만 보낸다.

## ③ 눌렀을 때 여는 주소

```
data.url (없으면 "/me")
→ 이미 열린 창 중 URL 에 그것이 든 창이 있으면 focus, 없으면 openWindow
```

**새 앱에 `/me` 와 `/parent` 가 살아 있어야 한다.** 옛 SW 가 그리로 연다.

## ④ 알림 자취 회신 경로

```
POST /api/push/seen     { "r": 123, "opened": true|false }     credentials: "include"
```

- push 를 **받은 때** → `opened: false`
- 알림을 **누른 때** → `opened: true`
- **실패해도 조용히 넘어간다** (`.catch(() => {})`) — 세는 일 때문에 알림이 안 뜨면 본말이 뒤집힌다

⚠️ **새 앱에 `/api/push/seen` 이 없으면** 옛 SW 의 회신이 404 로 사라진다.
알림은 뜨지만 **「읽음」이 영영 안 쌓인다.** 오류도 안 난다.

## ⑤ ⚠️ 계획에 없던 규칙 — 잠금화면에 내용을 안 띄운다

원장님 2026-08-07 — **「미리보기에서 내용 알 수 없게 해줘. 그냥 공지사항 전달사항.
눌러서 어플 들어와야 알 수 있게.」**

```js
const safe = { ...(await withAcademy(supabase, payload)), body: OPEN_TO_SEE };
// lib/notify.js:  export const OPEN_TO_SEE = "앱에서 확인해주세요.";
```

**본문을 보내는 자리에서 통째로 갈아 끼운다.** 부르는 곳이 여덟 군데라
각자 조심하게 하면 **언젠가 한 곳이 빠지고 그 한 곳이 사고가 된다.**

**왜** — 알림 미리보기는 **폰을 안 열어도 보인다.** 옆 사람에게도 보이고,
**형제 폰에 어머니가 로그인해 두신 집에서는 아이가 본다.**
거기 「단어 6/20」이나 「오늘 태도가…」가 적히면 **그건 우리가 흘린 것이다.**

→ **새 앱 `notify` 도 같은 자리에서 지운다.** 자동 검사에 넣는다.
→ **선생님께 가는 알림은 그대로 둔다** — 원장님 폰이고, 무슨 일인지 바로 보여야 답을 하신다.

## 새 앱이 전환 첫 주에 지킬 것 — 한 줄 요약

| | |
|---|---|
| 1 | SW 를 **`/sw.js` 루트 스코프**로 내고 **옛 등록을 지우지 않는다** |
| 2 | **`skipWaiting()` + `clients.claim()`** 을 그대로 둔다 |
| 3 | 보내는 글을 **`{title, body, tag, url, r}`** 모양 그대로 — **첫 주만이라도** |
| 4 | **`/api/push/seen` · `/api/icon/192` · `/me` · `/parent`** 를 새 앱에 만든다 |
| 5 | **본문은 `notify` 한 곳에서 「앱에서 확인해주세요.」로 갈아 끼운다** |

**새 모양으로 바꾸는 것은** 「전 기기가 새 SW 로 넘어갔다」를 **알림 자취로 확인한 뒤에** 한다.
