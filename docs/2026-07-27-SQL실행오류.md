## 원장님이 만난 에러

```
ERROR: 42P01: relation "public.daily_report_items" does not exist
```

`한번에_실행.sql` 은 **0008 부터** 들어 있습니다. 기초 테이블(0001~0007)이 없는
프로젝트에 이걸 붙이면 첫 줄부터 없는 표를 고치려 들어서 이 에러가 납니다.

**Supabase 는 붙여넣은 SQL 을 한 덩어리로 실행합니다.** 중간에 에러가 나면
**아무것도 반영되지 않습니다.** DB 가 망가진 게 아닙니다.

### 고친 방법 — 파일을 하나로

`설정 → Supabase SQL` 이 이제 **`SETUP_ALL.sql`** 을 보여줍니다.
0001 부터 지금까지가 다 들어 있어서 **새 프로젝트든 쓰던 프로젝트든 이거 하나면** 됩니다.
`한번에_실행.sql` 은 저장소에 남겨두되 머리말에 경고를 붙였습니다.

> **2026-08-28 — `한번에_실행.sql` 은 아예 지웠습니다.** 경고를 붙여둬도
> 고를 수는 있는 두 번째 벌이라 「부분 실행」 사고의 씨앗이었습니다.
> 이제 합본은 **`SETUP_ALL.sql` 하나뿐**입니다. 위 에러를 만나셨다면
> 그거 하나만 붙여넣으시면 됩니다.

## 진짜 Postgres 에 돌려봤더니 두 개가 더 나왔습니다

에러가 났다길래 로컬에 Postgres 를 띄우고 **세 번** 돌려봤습니다.
한 번은 "돌아가나", 두 번째는 "다시 돌려도 안전한가",
세 번째는 "seed 가 계속 늘어나지 않나".

### ① ON CONFLICT 가 부분 인덱스를 못 찾았다

```
ERROR: there is no unique or exclusion constraint matching the ON CONFLICT specification
```

0029 에서 만든 인덱스가 **부분 유니크**였습니다.

```sql
create unique index ... on message_templates (key) where key is not null;
insert ... on conflict (key) do nothing;              -- ✗ 못 찾는다
insert ... on conflict (key) where key is not null    -- ✓ 조건을 같이 적어야 한다
```

**이건 SETUP_ALL 을 처음 실행하는 사람 전부가 만났을 에러입니다.**

### ② 실행할 때마다 문자가 3배로 늘고 있었다

0017 의 seed 가 `on conflict do nothing` 인데 **name 에 유니크가 없어서**
조건이 걸릴 데가 없었습니다. 세 번 돌리니 이렇게 됐습니다.

```
교재 구매 안내        ← 3개
레벨테스트 등원 안내  ← 3개
레벨테스트 하원 안내  ← 3개
```

이름에 유니크 인덱스를 걸고(`where active`), 있던 중복은 지우게 했습니다.
**원장님 DB 에 이미 중복이 있어도 다시 실행하면 정리됩니다.**

### ③ 할일 분류도 같은 문제

`수업 준비`, `기타` … 8개가 3배로 늘어 24개가 되어 있었습니다. 같은 방법으로 고쳤습니다.

## 앞으로 안 생기게

`scripts/check-sql.sh` 를 만들어 `check-pages.sh` 에 넣었습니다.
진짜 Postgres 를 띄워서 **세 번 실행**하고, 늘어난 seed 가 있는지까지 봅니다.

```
== 4) SQL (진짜 Postgres 에 세 번 실행) ==
  세 번 다 통과
  늘어난 seed 없음
```

빌드만 통과하고 SQL 은 아무도 안 돌려본 채 나가던 것을 막습니다.
