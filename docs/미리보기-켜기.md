# 새 앱을 웹에서 여는 법 — 실제로 한 번 밟아 본 순서 (2026-09-03)

> 원장님이 「웹에서 보고 싶다」고 하셔서 처음으로 끝까지 밟았다.
> **막힌 자리마다 무엇이 없었는지 그대로 적는다** — 다음 사람이 같은 데서 또 헤매지 않게.

## 한 줄 요약

새 앱은 **`v2` 브랜치**이고, 버셀이 그 브랜치를 **미리보기(Preview)** 로 띄운다.
옛 앱(`main` · Production)은 **한 줄도 안 건드린다.**

## 밟는 순서 넷

| | 어디서 | 무엇 |
|---|---|---|
| 1 | 깃허브 | `git push -u origin v2` — **한 번도 안 올라가 있었다**(2026-09-03 실측) |
| 2 | 버셀 | 저절로 Preview 배포가 선다. 주소는 Deployments 탭 |
| 3 | 버셀 | **환경변수** — 아래 |
| 4 | 수파베이스 | **Exposed schemas 에 `v2` 더하기** — 아래 |

## 3. 버셀 환경변수 — ⚠️ `DATABASE_URL` 이 **아예 없었다**

버셀에 있던 것은 넷뿐이었다(실측):
`CLASSCARD_KEY` · `SUPABASE_SERVICE_ROLE_KEY` ·
`NEXT_PUBLIC_SUPABASE_URL` · `NEXT_PUBLIC_SUPABASE_ANON_KEY`

**까닭: 옛 앱은 `DATABASE_URL` 을 안 쓴다.** 그래서 넣을 일이 없었다.
새 앱은 **화면 11곳에서 DB 에 직접 붙는다**(설정·오늘·등원 관문·크론) — 그래서 새로 필요해졌다.

→ `DATABASE_URL` 을 **새로 만들고 Production·Preview·Development 셋 다** 켠다.
→ `SUPABASE_SERVICE_ROLE_KEY` 도 Preview 를 켠다.
→ ⚠️ **환경변수는 저장만으론 안 박힌다.** 그 브랜치를 **다시 배포**해야 들어간다.

⚠️ 증상이 이렇게 뜬다 — 화면이 스스로 말한다(대전제-0):
「⚠️ 설정을 못 읽었습니다 — DATABASE_URL 이 없다 (Vercel 환경변수)」

## 4. 수파베이스 — Exposed schemas 에 `v2`

`Project Settings → API → Exposed schemas` 가 `public` 뿐이었다.
**`v2` 를 더한다.** 빼는 것이 아니라 더하는 것이라 **옛 앱은 그대로 산다.**

⚠️ 증상: 「앱 설정이 아직 덜 됐습니다 (v2 스키마 노출 안 됨)」

그래서 **새로 가입할 필요가 없다.** 이것이 「같은 프로젝트, 다른 스키마」로 지은 값이다.

## ⚠️ 미리보기는 원장님 계정으로 잠겨 있다

버셀 배포 보호가 켜져 있어 **주소만으로는 안 열린다** — 원장님이 버셀에 로그인한 브라우저에서만 열린다.
아이 실물 리허설(6단계 2번)을 할 때 그 3명이 지나갈 길을 따로 정해야 한다.
