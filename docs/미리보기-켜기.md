## 한 줄 요약

새 앱은 **`v2` 브랜치**이고, 버셀이 그 브랜치를 **미리보기(Preview)** 로 띄운다.
옛 앱(`main` · Production)은 **한 줄도 안 건드린다.**

## 3. 버셀 환경변수 — ⚠️ `DATABASE_URL` 이 **아예 없었다**

버셀에 있던 것은 넷뿐이었다(실측):
`CLASSCARD_KEY` · `SUPABASE_SERVICE_ROLE_KEY` ·
`NEXT_PUBLIC_SUPABASE_URL` · `NEXT_PUBLIC_SUPABASE_ANON_KEY`

**까닭: 옛 앱은 `DATABASE_URL` 을 안 쓴다.** 그래서 넣을 일이 없었다.
새 앱은 **화면 11곳에서 DB 에 직접 붙는다**(설정·오늘·등원 관문·크론) — 그래서 새로 필요해졌다.

→ `DATABASE_URL` 을 **새로 만들고 Production·Preview·Development 셋 다** 켠다.
→ `SUPABASE_SERVICE_ROLE_KEY` 도 Preview 를 켠다.
→ ⚠️ **환경변수는 저장만으론 안 박힌다.** 그 브랜치를 **다시 배포**해야 들어간다.

⚠️ 증상이 이렇게 뜬다 — 화면이 스스로 말한다(대전제-0):
「⚠️ 설정을 못 읽었습니다 — DATABASE_URL 이 없다 (Vercel 환경변수)」

⚠️ **2026-09-05 밤 실제로 뜬 것**: 일정 화면에 「DB 에 못 붙었습니다 — getaddrinfo ENOTFOUND base」. 값은 있는데 **주소(호스트)가 `base`** 로 잘려 있었다 —
값을 잘못 붙여 넣은 것이다. Supabase → Project Settings → Database → Connection string(URI) 를 **통째로** 다시 넣고(`postgresql://postgres…@db.<ref>.supabase.co:5432/postgres` 또는 pooler 주소),
**그 브랜치를 다시 배포**해야 박힌다. (⚠️ 2026-09-05 밤부터 짓는 새 v2 는 화면에서 DATABASE_URL 을 안 쓴다 — 검사 스크립트만 쓴다. 이 값은 옛 v2 빌드에만 필요했다.)

✅ **해결(9/5 밤, 원장님 「버셀 고쳤고 /plan 정상작동해」)** — 아래 손 셋으로 옛 앱이 운영 주소로 돌아왔다. 경위: ⚠️⚠️ **원장님 확인(9/5 밤) — 그 화면이 뜬 주소는 `chloe-english.vercel.app`, 즉 운영 주소였다.** 「DB 에 못 붙었습니다」는 main 에 없는 문구라 **운영이 v2 빌드를 보이고 있는 것**이고, 원장님이 쓰는 옛 앱이 그 주소에서 죽어 있는 것이다(옛 앱은 학생·학부모에게 안 나갔다 — 원장님 9/5). 되돌리는 손 셋(Vercel, 원장님만 할 수 있다):
1. **Settings → Environments → Production** 을 열면 **「Branch Tracking」** 칸이 있다(원장님 9/5 밤 실측: Settings → Git 에는 Production Branch 가 없다 — Connected Git Repository · Git Commits · LFS · Deploy Hooks 뿐). 거기가 `main` 인지 본다. 아니면 `main` 으로 고치고 Save.
2. Deployments → `main` 의 마지막 배포(8/31) → ⋯ → **Promote to Production** (또는 Redeploy). 브랜치 설정만 바꾸면 **저절로 안 돌아온다** — 이 한 번이 있어야 한다.
3. 폰에서 `chloe-english.vercel.app` 을 열어 옛 앱(일정 화면)이 정상인지. v2 는 Deployments 의 **Preview 주소**로 본다.

**맞게 됐나 보는 자리 셋**(원장님 9/5 「내가 제대로 설정했는지 어떻게 확인해?」):
1. **Deployments** 맨 위 Production(「Current」)이 브랜치 `main` · 8/31 커밋이면 맞다.
2. **Settings → Environments → Production → Branch Tracking** 이 `main`.
3. 그 뒤 v2 에 푸시된 배포가 목록에 **Preview** 로 뜨면 맞다. **Production** 으로 뜨고 「Canceled」 + 로그에 「전환일 전 — v2 는 운영(Production)으로 짓지 않는다」가 보이면 아직 v2 를 보고 있는 것이다(막이가 대신 막은 것).
폰의 옛 앱(홈 화면 아이콘)도 한 번 열어 본다 — 같은 주소라 같이 살아난다.

**되풀이 막이(대전제-13)**: `vercel.json` 의 ignoreCommand 가 `V2_PRODUCTION_OK=1` 없이는 v2 의 **운영 빌드를 건너뛴다**(미리보기는 그대로 선다). 전환일에 Vercel 환경변수 `V2_PRODUCTION_OK=1`(Production)을 켜고 Production Branch 를 `v2` 로 — 코드는 안 고친다. 미리보기를 손으로 Promote 하는 것은 못 막는다.

## 4. 수파베이스 — Exposed schemas 에 `v2`

`Project Settings → API → Exposed schemas` 가 `public` 뿐이었다.
**`v2` 를 더한다.** 빼는 것이 아니라 더하는 것이라 **옛 앱은 그대로 산다.**

⚠️ 증상: 「앱 설정이 아직 덜 됐습니다 (v2 스키마 노출 안 됨)」
