# 대충 말씀하시면 — 내가 되짚어 드리고 시작한다 (2026-09-03)

> 원장님: 「앞으로 클로이 영어 웹 앱 제작에 효과적인 언어로 프롬프트를
> 변경해줘. 내가 자연어로 대충 설명 하면 니가 빠르고 효율적이고 정확한
> 프롬프트로 바꿔줘. 필요시 피드백 요구해.」

**원장님이 외우실 양식은 없다.** 하시던 대로 말씀하시면 된다. 바꾸는 것은
내 일이고, 바꾼 것을 **짧게 되짚어 보여드린 뒤** 시작한다. 되짚은 것이
틀렸으면 **그 줄만** 고쳐 말씀하시면 된다 — 처음부터 다시 설명하실 일은 없다.

---

## 무엇을 「효과적인 프롬프트」라고 할 것인가

먼저, 이 앱에서 실제로 사고가 났던 자리를 본다
(`docs/PRINCIPLES.md`, `scripts/check-dup.mjs` 머리말에 남아 있는 것들):

| 실제로 났던 사고 | 결과 |
|---|---|
| 학교 견주기가 **세 벌** | 아이가 시험기간에서 통째로 빠짐 |
| 권한 판단이 **열두 벌** | 조교가 되는 자리·안 되는 자리가 뒤섞임 |
| SQL 오류 판단이 **서른한 벌** | 어떤 화면은 안내 대신 날 오류를 보여줌 |
| 왕복을 한 줄씩 차례로 기다림 | 「모든 페이지의 로딩 자체가 느려」 |
| 빌드는 통과 | 그런데 화면이 터짐 |

**이 중에 원장님 말씀이 짧아서 난 것은 하나도 없다.** 전부 내가 **이 일이
어느 판단에 얹히는지 정하지 않은 채 코드부터 쳐서** 났다.

그러니 이 앱에서 좋은 프롬프트는 **말이 긴 것이 아니라 셋이 박힌 것**이다.

1. 이 일이 얹히는 **판단** — 이미 있나, 어디 사나 (`lib/…`)
2. 그 판단을 읽는 **소비처** 전부
3. 다 하고 나서 **무엇으로 확인**하나 (검사 + 실제 화면)

셋 다 **원장님이 아니라 내가 채운다.** 원장님은 1·2·3 을 모르셔도 되고,
아실 이유도 없다. 원장님이 주시는 것은 **「무엇이 지금 불편한가」** 하나뿐이고,
그게 있으면 나머지는 저장소에서 나온다.

## 두 갈래 — 대부분은 한 줄, 걸리면 여섯 줄

말씀 하나를 들으면 먼저 **A 인지 B 인지**부터 가른다.

### 갈래 A — 한 줄로 되짚고 바로 한다 (기본)

문구·색·크기·정렬·한 화면 안의 단추 하나. 되짚기는 한 줄이면 된다.

```
▸ 오늘 수업(/today) 출결 칩의 결석 글자를 키웁니다.
  확인 check-fontsize.mjs + 화면. 바로 합니다.
```

### 갈래 B — 여섯 줄로 되짚고, **확인받고** 한다

**B 로 가는 조건. 하나라도 걸리면 B 다.**

1. CLAUDE.md 「판단이 사는 곳」 표에 있는 파일을 건드린다
2. 같은 값을 읽는 자리가 **두 곳 이상**이다 (원칙 1)
3. **속도 대원칙 넷** 중 하나에 닿는다 (원칙 6 · `check-speed.mjs`)
4. **실제 세계 규칙**이 걸린다 — 시험·학교·수강료·학사일정 (원칙 4-4)
5. **새 화면**이거나 **새 표(DB)** 다
6. 예외를 하나 더 붙이는 일이다
   → **세 번째 예외면 B 도 아니고 멈춘다.** 설계가 틀렸다는 신호다 (원칙 4-3)

**애매하면 B 다.** A 로 잘못 가면 사고가 나고, B 로 잘못 가면 30초 더 쓴다.

## 갈래 B 되짚기 양식 (여섯 줄 + 여쭐 것)

```
■ 무엇·어디   한 줄. 화면 경로까지 («/parent 에 …»)
■ 지금 → 나중  지금 이렇게 보인다 → 이렇게 보여야 한다
■ 판단        lib/… (이미 있음 → 그곳을 고침 / 없음 → 새로 둘 자리)
■ 소비처 n곳   그 판단을 읽는 자리 전부. grep 한 결과를 그대로
■ 경계        빈 값 · 중복 · 학년 없음 · 권한 · 종이
■ 확인        scripts/check-*.mjs + 눈으로 볼 화면 경로
■ 여쭐 것     하나. 없으면 «없음 — 바로 시작합니다»
```

**원장님이 실제로 읽으실 줄은 둘이다** — 「지금 → 나중」 과 「여쭐 것」.
나머지 넷은 **내가 나를 붙잡으려고** 적는 것이니 훑고 넘기셔도 된다.
그 넷이 화면에 적혀 있어야 내가 건너뛰지 못한다.

원장님이 이 말을 쓰시면 **새로 만들지 않고 그 파일을 고친다** (원칙 1).

## 말이 모자랄 때 — 의도를 모르면 묻고, 세부가 비면 정해서 내민다

> 원장님 (2026-09-05): 「이제부터 내가 하는 모든 말은, 효과적이고 빠르게 의도한
> 결과값을 낼 수 있는 프롬프트로 바꾸어서 알아들어. **의도가 뭔지 모르면 물어보고**
> 바꿔서 이해해. 클로드 전체규칙이야.」

**둘을 가른다.** 「무엇을 원하시나」(의도)가 안 잡히면 **한 줄로 되묻는다** — 짐작으로
시작하면 엉뚱한 것을 다 만든 뒤에 안다. 「어떻게」(세부)만 비면 아래처럼 **내가
정해서 내민다.** 이 규칙은 앱 고치기만이 아니라 **질문·검토·문서·목업 전부**에 적용한다.

말씀에 안 들어 있어서 **늘 비는 자리가 넷**이다. 이걸 질문 넷으로 돌려
드리면 원장님 일이 늘어난다. **내가 답을 정해 적고, 아니면 아니라고만
하시게 한다.**

1. **누구 화면인가** — 원장·강사·조교·학부모·학생.
   권한이 다르면 같은 화면이 다른 화면이다 (`lib/guard.js`)
2. **언제 기준인가** — 오늘 · 이번 주 · 이번 달 · 학기 · 연도
3. **없을 때 어떻게 보이나** — 자료가 0줄일 때 (원칙 7-3)
4. **종이로도 나가나** — 화면만인가, 인쇄까지인가

**진짜로 여쭙는 것은 하나뿐이다** — 어느 쪽으로 정해도 **나중에 되돌리기
비싼 것**. 그것만 「여쭐 것」 줄에 적는다.
여쭐 것이 둘 이상이면, 그건 내가 아직 안 알아본 것이다. 더 알아보고 하나로 줄인다.

### 검토형 — 「~있어?」 「~검토 못 했어」

원장님: 「칸반기능이 현재 효과적으로 구현된건지 제대로 검토를 못했어」

**끝을 목록으로 정하고, 범위·갈래·근거·경계를 박는다.** 의견(「더 좋다」)이 아니라
근거가 붙는 것만 내놓게 만든다.

```
■ 무엇·어디   칸반 = 목업 06 내 할 일 보드 · 06c 표의 보기 · 04 자료 보드 — 두 층(코드 / 설계)
■ 지금 → 나중  「효과적인지 모른다」 → 코드에 있나/없나 + 설계가 원장 일을 줄이나, 목록으로
■ 판단        lib/todo.js board·myTodos · 인수인계 실측 「보드 생김새 없음 — 세로 목록」
■ 경계        할 일 0개 · 마감 지난 것 30개 · 같은 아이 5개 · 폰 · 자동 생긴 카드
■ 확인        규칙 번호(대전제-3·8) · 동선(아침 대시보드 → 수업 전 → 수업 후)
■ 여쭐 것     없음 — 원장님이 이미 확정한 것(노션식 · 칸반은 표의 보기 하나)은 안 뒤집는다.
              이미 물어둔 미결은 다시 안 묻는다
```

「효과적」의 잣대는 내가 정하지 않는다 — **대전제-3(원장 일이 적어지는 쪽) ·
대전제-8(한눈에·빠른가·클릭 안 늘었나)** 이 잣대다.

## 이 문서가 어긋나면 잡는 검사

`node scripts/check-prompt.mjs` — 위 말 옮김표가 **거짓말이 되는 것**을 막는다.
`lib/who.js` 가 옮겨졌는데 표는 그대로면, 나는 원장님께 **없는 파일을**
되짚어 드리게 된다. 표가 가리키는 파일·함수·검사가 실제로 있는지 기계가 본다.
`bash scripts/check-pages.sh` 안에서 같이 돈다.
