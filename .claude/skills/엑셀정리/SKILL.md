# 엑셀정리

앱에 올릴 파일을 다루는 일. **머릿속 양식이 아니라 코드가 아는 양식**에 맞춘다.

## 왜 이렇게까지 하나

이 앱에서 엑셀은 **조용히 실패한다.** 실제로 겪은 것들 —

- 상담일지 CSV 193줄 중 **52줄이 사라졌다.** 오류도 없고 「141줄 옮길 수 있음」 이라고 멀쩡히 떴다 (엑셀 라이브러리가 날짜를 미국식으로 고쳐 쓴 탓)
- 단원 엑셀의 「1-25」 가 **1월 25일**로 바뀌어 분량이 영영 틀린 채로 남았다
- 열 이름 하나가 안 맞아 **1957줄이 0줄**로 읽혔다

전부 **오류가 안 난다.** 그래서 눈으로 훑는 것으로는 못 잡고, 늘 원장님이 며칠 뒤에 발견하신다. 검증을 코드로 하는 까닭이 이것이다.

## 순서

### 1. 앱이 지금 뭘 갖고 있는지 먼저 받는다

새로 만들기 전에 **이미 들어 있는 것**을 봐야 한다. 안 그러면 같은 교재가 두 벌이 되거나, 있는 것을 덮어쓴다.

앱 화면에 내려받기가 있다 — 교재·단원 화면의 **「⬇️ 지금 교재 내려받기」 · 「⬇️ 지금 단원 내려받기」**. 원장님께 그걸 눌러 받아서 보내달라고 하면 된다.

내려받은 파일은 **그대로 다시 올릴 수 있는 모양**이다. 이름이 같은 것은 고쳐지고 없는 것만 새로 생긴다. 그래서 「고쳐서 다시 올리기」 가 늘 「처음부터 새로 만들기」 보다 안전하다.

내려받기가 없는 자리를 만나면, 그건 앱에 뚫린 구멍이다 — 스킬을 멈추고 그 버튼을 먼저 만드는 편이 낫다.

### 2. 양식은 `lib/import*.js` 에서 읽는다

열 이름을 짐작하지 않는다. 각 파서가 **자기가 아는 열 이름 표(HEADER_MAP)** 와 **내보낼 머리줄(*_HEADERS)** 을 갖고 있다.

| 무엇 | 파서 | 머리줄 |
|---|---|---|
| 교재 | `lib/importTextbook.js` `parseTextbookAoA` | `TEXTBOOK_HEADERS` |
| 단원 | `lib/importUnit.js` `parseUnitAoA` | `UNIT_HEADERS` |
| 학생 | `lib/importParse.js` `parseAoA` | `TEMPLATE_HEADERS` |
| 반 | `lib/importClass.js` `parseClassAoA` | `CLASS_HEADERS` |
| 성적 | `lib/importScore.js` `parseScoreAoA` | — |
| 상담 | `lib/importInquiry.js` `parseInquiryAoA` | — |

HEADER_MAP 은 같은 뜻의 여러 이름을 받아준다(「교재명」 「교재」 「이름」). 그러니 **먼저 있는 그대로 돌려보고**, 안 잡히는 열만 고친다. 파일을 통째로 다시 쓰는 것은 마지막 수단이다.

### 3. 앱은 **첫 시트만** 읽는다

`lib/readSheet.js` 가 `wb.SheetNames[0]` 하나만 본다. 시트가 여럿인 파일(요약·기본정보·교재별 시트…)은 **첫 시트가 우리 것이 아니면 0줄로 읽힌다.**

그래서 내보낼 때는 **한 파일에 한 시트**로 만든다. 교재와 단원은 파일을 따로 만들어 **교재 먼저, 단원 나중**에 올린다 (단원만 올려도 교재는 생기지만 영역·레벨이 빈 채로 생긴다).

### 4. 검증은 스크립트로

```bash
node .claude/skills/엑셀정리/scripts/check.mjs <파일…>
```

무엇을 보는지는 `scripts/check.mjs` 안에 적혀 있다. 새로 겪은 함정이 생기면 여기 한 줄 늘린다 — 다음에 같은 데서 안 넘어진다.

파일이 둘 이상이면 서로 **맞물리는지**까지 본다 (단원의 교재명이 교재 파일에 다 있나 — `lib/bookName.js` 의 `bookKey` 로 견준다. 「리딩튜터」 와 「리딩 튜터」 는 같은 책이다).

### 5. 진짜로 올려본다

파서가 통과해도 **화면이 쓸 만한지**는 다른 문제다. 단원 나무가 어떻게 보이는지, 숙제 낼 때 그 단원을 고를 수 있는지는 눌러봐야 안다.

```bash
bash scripts/e2e/up.sh
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:55442 \
NEXT_PUBLIC_SUPABASE_ANON_KEY=$(node scripts/e2e/token.mjs anon) \
npx next dev -p 3300
```

브라우저로 올릴 때 **파일 이름을 영문으로 바꿔서 넘긴다.** Playwright 의 `setInputFiles` 가 한글 경로를 조용히 못 문다 — 「No file chosen」 인 채로 지나가고 오류는 안 난다. 여기서 한참 헤맸다.

올린 뒤에는 표를 직접 세어 본다:

```sql
select t.name, count(*) filter (where u.parent_id is not null) as 단원,
       count(*) filter (where u.total_pages is not null) as 분량있음
  from textbook_units u join textbooks t on t.id = u.textbook_id group by t.name;
```

### 6. 정리한 파일은 저장소에 두지 않는다

`.gitignore` 에 이미 `/클로이영어_*.xlsx` 가 있다. 원장님께는 `SendUserFile` 로 보낸다.

## 정리할 때 판단이 갈리는 자리

**「한 줄이 무엇이냐」 를 원장님께 여쭙는다.** 이게 제일 중요하고, 코드로는 못 정한다.

같은 교재를 두고도 세는 법이 여럿이다 —

```
1957줄   Unit 01 ▸ 본책 / Unit 01 ▸ 워크북      (따로)
1419줄   Unit 01 be동사의 현재형과 과거형        (합침)
```

원장님은 「**단원을 기준으로 공부한다. 워크북은 단원 마지막**」 이라고 하셨다. 그래서 한 Unit 이 한 줄이고, 워크북 쪽수는 그 단원 **분량에 더하고**, 어디를 푸는지는 **활동 칸**에 남긴다 (`워크북 p.4-6`). 그러면 숙제 낼 때 바로 보인다.

새 교재도 이 규칙으로 맞춘다. 다르게 세야 할 것 같으면 짐작하지 말고 여쭙는다.

**빈 칸은 채우지 않는다.** 모르는 값을 그럴듯하게 지어 넣으면 그게 데이터가 된다. 비워두면 화면이 「—」 로 보여주고, 그건 「모른다」 는 정직한 표시다.

**앱에 없는 개념은 억지로 넣지 않는다.** 남이 만든 파일에는 우리에게 없는 칸이 섞여 있다(단원유형·교재ID·순번 …). 쓰이는 자리가 없으면 버리거나, 사람이 읽을 값이면 **활동·비고 같은 자유 칸에 글자로** 남긴다. 칸을 새로 만드는 것은 그 값을 **실제로 쓰는 화면이 생길 때**다.

## 결과를 말할 때

숫자로 말한다 — 몇 줄이 몇 개가 되는지, 사라지는 줄이 몇인지, 못 알아본 열이 무엇인지. 「양식 맞습니다」 만으로는 원장님이 확인할 방법이 없다.

고치다 잡은 것이 있으면 **그것도 말한다.** 이 일은 조용한 실패를 잡는 일이라, 무엇을 잡았는지가 결과의 일부다.
